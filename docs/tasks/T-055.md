# T-055 — Parameter di proses `api`: cache atau baca per permintaan? (O-018)

Status: **DONE** (17 Okt 2026) — diputuskan: **tetap dibaca per permintaan**, tanpa cache.
Prioritas: P1 (keputusan arsitektur yang memblokir O-018).
Keputusan terkait: D-052.

## Kenapa

O-018 tidak bisa dikerjakan sebelum pertanyaannya dijawab. `ParamService`/`param_cache` (cache
in-proc + invalidasi lewat `NOTIFY platform_param_changed`) ada di `modules/platform`, tetapi **nol
pemakai di `apps/api`** — satu-satunya konsumen kanal itu adalah test `itparamservice`; proses `api`
membaca parameter dari DB lewat `param_repo`. Jadi pilihannya bukan "menambahkan `LISTEN`",
melainkan "bangun cache lintas-proses" atau "jangan".

## Rencana dan hasil

- **Analisis jalur baca** — `settingsOf`
  (`modules/platform/infrastructure/auth_service.nim:50-65`) melakukan 6 pembacaan baris-tunggal per
  panggilan, dan hanya dipanggil di jalur auth (`apps/api/src/handlers_auth.nim:64` login, `:115`
  GET session, `:179` ganti kata sandi); `realtimeLimits` dipanggil sekali saat start
  (`apps/api/src/main.nim:478-479`). Jadi 6–8 lookup per **permintaan auth**, bukan per permintaan
  umum seperti dugaan awal.
- **Keputusan**: parameter tetap dibaca per permintaan; cache lintas-proses tidak dibangun. Pemicu
  tinjau ulang terukur dicatat di D-052.
- **Implementasi**: tidak ada kode baru — dan memang tidak boleh ada cache yang tak dipakai.

## Bukti

- Tiap `activeParamInt` = satu query `activeValueSql`
  (`modules/platform/infrastructure/param_repo.nim:109-113`, SQL `:26-32`). Query menyaring
  `status IN ('ACTIVE','SUPERSEDED')`, sedangkan indeks parsial `param_value_lookup_idx`
  (`modules/platform/migrations/0004_platform_parameter.sql:75-77`) berpredikat `WHERE status='ACTIVE'`
  → **tidak** menopangnya. Namun tabelnya puluhan baris (10 definisi parameter di DB dev), jadi
  rencana sekuensial pun tidak terasa. Ini kelemahan indeks yang dicatat jujur, bukan alasan cache.
- Sifat opsi cache diperiksa di kode: `param_cache.nim` sengaja **tanpa TTL**, `NOTIFY` dikirim saat
  commit (`param_repo.nim:145-151`), dan PostgreSQL tidak memutar ulang notifikasi → notifikasi yang
  hilang = nilai basi **tanpa error**.
- Skala acuan: pilot 1 koperasi / 1 cabang / < 5.000 anggota, satu proses `api` (D-046).

## Sisa jujur

- Ini menutup O-018 **sebagai keputusan**, bukan sebagai implementasi. Bila salah satu pemicu D-052
  tercapai, keputusan ini harus dibuka kembali dengan pengukuran.
- `ParamService`/`param_cache` tetap ada dan tetap hanya dipakai test; menghapusnya bukan lingkup
  task ini (dipakai `itparamservice`) dan jadi kandidat task tersendiri bila cache diputuskan tidak
  akan pernah dibangun.
- O-017 (tipe id cabang) tidak disinggung di sini.
