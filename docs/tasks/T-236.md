## Scope

One shared `MoneyInput` on top of the T-286 `Input` semantics: label carries the currency once
("Nominal (IDR)"), `inputmode="decimal"`, no grouping in the editable value, `parseMoneyInput`
at submit only, error through `aria-describedby` and `aria-invalid`, no per-keystroke live region.
Migrate the four call sites above.

Not in scope: `Money` display, `AmountSummary`, ledger or totalling rules, DataTable money columns
(T-289), and any change to the parse contract without its own decision.

  forbidden in editable values).

  lesson: a green local gate did not catch a dead focus move).

### Open item recorded for the reviewer

The task text says "thousand separators in the editable value" and Acceptance names
`"1.234.567,89"` as a valid amount, while the DoR's own evidence anchor
`docs/design/04-a11y-and-copy.md:26` lists "thousand separators in the editable value" under
MoneyInput **Forbidden**, and `parseMoneyInput` (fence: reuse, do not rewrite) rejects every
grouped form (`"150.000"` -> `too_precise`, `"1.234.567,89"` -> `invalid_format`). Implemented the
conservative side: no re-formatting per keystroke, no second parser, parse at submit only, so a
grouped paste shows the parse error instead of being guessed. If grouping is wanted, it needs a
parse-contract decision (D-xxx) and Fajar correcting the a11y table first.

Not fixed here, outside the fence: `"150.000"` falls to `too_precise`, not `invalid_format`, so the
message shown for that input is misleading. It needs a parser-contract decision, not a component
change.
