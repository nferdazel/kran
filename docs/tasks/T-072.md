Status: **DONE** (20 Okt 2026). Reviewer putaran 2: **APPROVE** tanpa BLOCKER/MAJOR. Spec §8.1, §9.2, §10.5, §23.

## Scope

1. Modul baru `ledger` (scaffold sudah dijalankan), migrasi `0001_ledger_init.sql`:
   - `ledger.coa_account`: `code` unik, nama, `account_type`
     (`ASSET`/`LIABILITY`/`EQUITY`/`REVENUE`/`EXPENSE`), `normal_side` (`DEBIT`/`CREDIT`),
     `postable` (akun induk/header tidak boleh dipakai posting), `status`, audit kolom.
     CHECK menjaga `normal_side` konsisten dengan `account_type` (ASSET/EXPENSE = DEBIT,
     LIABILITY/EQUITY/REVENUE = CREDIT) — invarian akuntansi, bukan setelan institusi.
   - `ledger.period`: rentang tanggal **inklusif** `[starts_on, ends_on]`, status
     `OPEN`/`CLOSED`, `closed_at`/`closed_by`; `EXCLUDE USING gist (daterange(...) WITH &&)`
     menolak periode tumpang tindih (butuh `btree_gist`, sudah terpasang).
2. Migrasi `0002_ledger_coa_base.sql`: COA awal **idempoten** (`ON CONFLICT DO NOTHING`),
   bertanda `NEEDS-COMPLIANCE-REVIEW` (REG-011 `V!`, SAK EP belum diverifikasi). Ditaruh di
   migrasi, bukan `packs/*/seed` — direktori seed pack hanya diterapkan dengan `--dev` sehingga
   produksi tidak akan pernah mendapatkannya (O-066).
3. Parameter baru: `ledger.coa.code_pattern` (regex, GLOBAL/INSTITUTION). Format kode COA adalah
   kebijakan institusi (spec §10.5: format kode), jadi bukan konstanta di kode; pola divalidasi
   saat dipakai (`std/re`), pola rusak = 500 (konfigurasi), kode tidak cocok = 400.
4. Izin baru (`modules/platform/migrations/0015_platform_rbac_ledger.sql`):
   `ledger.coa.read`, `ledger.coa.manage`, `ledger.period.read`, `ledger.period.manage`
   (semua ke `platform_admin`).
5. API (composition root `apps/api`; modul `ledger` tanpa impor internal `platform`):
   - `GET  /api/v1/ledger/coa` — daftar akun (filter `type`, `postable`).
   - `POST /api/v1/ledger/coa` — buat akun; kode duplikat → 409; audit `ledger.coa.create`.
   - `GET  /api/v1/ledger/periods` — daftar periode.
   - `POST /api/v1/ledger/periods` — buka periode; tumpang tindih → 409; audit
     `ledger.period.open`.
   - `POST /api/v1/ledger/periods/{periodId}/close` — tutup periode; wajib `reason`, menulis
     `closed_at`/`closed_by`, audit `ledger.period.close` + event `period.closed` (outbox,
     transaksi yang sama).
6. Semua endpoint bersifat **institusi** (tanpa cabang): COA/GL tidak dimiliki cabang pada Fase 1
   (spec §9 `coa_account`), berbeda dari `party` yang per cabang.

## Asumsi (dicatat, bukan ditebak)

- Urutan penutupan periode (tidak boleh menutup periode lebih awal saat periode sebelumnya masih
  terbuka) **belum** ditegakkan di T-072; orkestrasi EOD/EOM ada di `daycloser` (Fase 5). Yang
  ditegakkan sekarang: tidak ada rentang tumpang tindih.
- `postable=false` untuk akun header/induk; hierarki (`parent_code`) **belum** ada — ditambahkan
  saat laporan keuangan butuh (T-075/T-076).
- Tidak ada multi-currency, tidak ada saldo, tidak ada jurnal: T-073/T-075.
- Kode COA tidak boleh diubah setelah dibuat (tidak ada endpoint update); koreksi = akun baru +
  nonaktifkan yang lama (jejak audit terjaga). Aturan penuh "expand/contract" COA menyusul.
- COA awal hanya **contoh struktur** untuk pilot; angka/kode final menunggu compliance owner
  (REG-011), jadi ditandai `NEEDS-COMPLIANCE-REVIEW` di berkas migrasi.
