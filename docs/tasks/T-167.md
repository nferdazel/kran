# T-167 — PPAP/CKPN: penyisihan per golongan + jurnal selisih

**Status**: READY (1 Nov 2026) · **Keputusan**: D-180 butir 3 (tarif sementara), D-184 (snapshot
harian) · **Deps**: T-166

## Scope

1. **Domain** (`modules/lending/domain/ppap.nim`, murni): `allowanceFor(outstanding, grade, rates)`
   — tarif per golongan dari parameter `lending.ppap.rates` (`["0","0.5","10","50","100"]` persen,
   urutan = urutan `Collectibility`), satu pembulatan half-to-even per pinjaman. Parameter rusak
   (jumlah tarif ≠ jumlah golongan, bukan desimal, negatif) → galat, bukan tarif nol.
2. **Parameter**: `lending.ppap.rates` (sudah ada, `NEEDS-COMPLIANCE-REVIEW`, REG-204 `V!`).
3. **Skema** (`lending/…`): `lending.ppap_snapshot` (`loan_id`, `business_date`, `grade`,
   `base_amount` = pokok berjalan, `rate_percent`, `allowance`, PK `(loan_id, business_date)`).
4. **Task day-close** `lending.ppap_provision` (`apps/api/src/daycloser_lending.nim`), **kritis**:
   - sumber: snapshot kolektibilitas tanggal itu (`T-166` sudah jalan; `dependsOn` menjadikannya
     kontrak registry, bukan kebetulan urutan) + `lending.loan_balance.principal_outstanding`;
   - selisih = `Σ allowance(tanggal ini) − Σ allowance(tanggal buku sebelumnya)`; satu jurnal per
     run dengan nominal `|selisih|`: `PpapProvisioned` bila bertambah, `PpapReleased` bila berkurang
     (jurnal pembalik, bukan jurnal negatif);
   - **idempoten**: PK snapshot per tanggal + kunci idempotensi jurnal `lending.ppap:<businessDate>`;
     run kedua tidak menambah baris/jurnal dan melaporkan `skipped`.
5. **COA** (`ledger/…`): `503 BEBAN PENYISIHAN PIUTANG` (EXPENSE) dan akun lawan
   `111 PENYISIHAN KERUGIAN PIUTANG`. **Keduanya `NEEDS-COMPLIANCE-REVIEW`.**

## Keputusan yang harus diambil, bukan ditebak

- **Akun lawan tidak bisa kontra-asset.** `ledger.coa_account` memaksa `ASSET → normal_side DEBIT`
  (`coa_normal_side_chk`) dan belum bisa memodelkan akun kontra (**O-075**). CKPN yang seharusnya
  kontra-piutang karena itu direpresentasikan sebagai akun `LIABILITY` sampai O-075 ditutup; ini
  **deviasi akuntansi yang harus disetujui pemilik/compliance**, dicatat di `docs/OPEN_ITEMS.md`
  dan `docs/ACCEPTED-LIMITS.md`, bukan disembunyikan di kode.
- **Dasar penyisihan = pokok berjalan** (`principal_outstanding`), bukan pokok + bunga tunggakan:
  bunga yang belum dibayar belum menjadi piutang yang diakui di modul ini.
- **Tarif final menunggu compliance** (REG-204 `V!`); seed sementara hanya untuk menguji mesin.
  Pilot data nyata tidak boleh memakai angka ini (O-001).

## Invarian yang diuji

- **Property**: `Σ allowance` per tanggal == `Σ base × rate` dengan pembulatan per pinjaman;
  selisih yang dijurnal == perubahan `Σ allowance` (Δ subledger == Δ GL), termasuk saat golongan
  membaik (jurnal pembalik) dan saat pinjaman lunas (allowance → 0).
- Run kedua tanggal yang sama: tidak ada snapshot/jurnal kedua, `skipped` dilaporkan.
- Parameter tarif rusak → task gagal dengan kode, bukan menyisihkan 0.
- Golongan tanpa tarif (mis. `LOSS` tidak ada di array) → gagal, bukan dianggap 0%.

## Non-goals

- Hapus buku/penghapusan piutang, CKPN kolektif per portofolio vs individual, dan pelaporan CKPN ke
  OJK (butuh format laporan yang belum ada).
- Perubahan `ledger.coa_account` untuk mendukung akun kontra (O-075).

## Kriteria selesai

- `tppap` (murni): tarif per golongan, pembulatan, parameter rusak, dasar nol.
- `itdaycloser_lending`: selisih bertambah → `PpapProvisioned`; golongan membaik → `PpapReleased`;
  run ulang tidak menggandakan; Δ snapshot == Δ jurnal; parameter rusak → task gagal.
- `./task check-fast`, `build`, `openapi`, `./task test`, `./task e2e` hijau.
