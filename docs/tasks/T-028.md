# T-028 — Kebijakan anti-enumerasi akun (O-034)

Status: READY
Prioritas: P1 (batch "Fase 0 tahan banting")

## Kenapa
Keputusan pemilik 15 Okt 2026 (D-034): status `locked`/`inactive` dibalas **hanya setelah** kata
sandi benar, dan akun tak dikenal menjalankan PBKDF2 tiruan supaya waktu responsnya tidak membedakan
keberadaan akun. Sekarang `locked`/`inactive` dibalas sebelum verifikasi kata sandi, dan user tak
dikenal melewati PBKDF2 (beda waktu terukur).

## Rencana
- `handlers_auth`/`auth_service`: verifikasi kata sandi dulu (dengan dummy hash berbiaya setara untuk
  user tak dikenal), baru tentukan respons: kata sandi salah → 401 generik; kata sandi benar tetapi
  akun terkunci/nonaktif → 403 dengan alasan.
- Pastikan pesan generik untuk kata sandi salah seragam (kode + i18nKey sama) dan audit
  `user.login_failed` tetap tercatat tanpa membocorkan status di respons.
- Test: (a) respons seragam untuk user tak dikenal vs kata sandi salah; (b) waktu respons dalam
  toleransi (mis. selisih median < 30% pada beberapa putaran); (c) akun terkunci dengan kata sandi
  benar tetap 403 `locked`; (d) akun terkunci dengan kata sandi salah → 401 generik.
- Perbarui kontrak bila deskripsi respons perlu diperjelas (tanpa menambah status baru).

## Kriteria selesai
- [ ] Keempat test di atas ada dan lulus, tanpa membuat CI flaky (pakai toleransi, bukan waktu absolut).
- [ ] Tidak ada perubahan kode keluar/status yang mematahkan klien; i18n id+en konsisten.
- [ ] `./task ci` hijau. Tandai `HUMAN-REVIEW-REQUIRED` (jalur auth).
