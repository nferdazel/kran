# T-035 — Migrasi contract & rollback (O-048)

Status: READY (rencana sudah memuat hasil recon; **belum ada kode**)
Prioritas: P3 (batch "Fase 0 tahan banting")
Titip: **HUMAN-REVIEW-REQUIRED** — menyentuh jalur migrasi produksi.

## Kenapa
Biner hanya punya jalur expand-only: `--up` **menolak** migrasi bertanda destruktif, dan
`ops/scripts/migrate.sh` menolak `--contract`/`--down` dengan kode 3 ("belum ada di biner"). Artinya
tidak ada jalur rollback skema sama sekali: bila deploy membawa migrasi bermasalah, satu-satunya
jalan adalah backup pra-deploy (expand-only). Untuk Fase 0 itu keputusan sadar (dicatat sebagai
O-048); task ini menutupnya.

## Fakta dari kode (recon 15 Okt 2026)
- `tools/dbtools/lib.nim` — pola direktif header sudah ada: `-- dbtools:destructive <alasan>`, dengan
  `destructiveStatements()` mendeteksi `drop `/`truncate `/` drop column`/` drop constraint`/` rename `.
  `applyMigrations()` mencatat `(migration_id, module, filename, seq, sha256, destructive, duration_ms)`.
  Urutan dari awalan nomor berkas (`parseSeq`). Berkas: `modules/*/migrations/NNNN_nama.sql` (kini 9).
- `apps/api/src/main.nim` — `destructivePending(status)` + `runMigrate`: `--up` menolak **pending
  destruktif** dengan kode 3 dan pesan yang menunjuk O-048.
- `ops/scripts/migrate.sh` — sudah mendokumentasikan `--contract --yes` dan `--down --yes [N]`, tapi
  menolaknya (kode 3). `ops/scripts/rollback.sh` ada, tetapi itu rollback **aplikasi** (rev), bukan skema.
- Uji: `tools/dbtools/tests/tdbtools.nim` + `tests/fixtures/` (pola fixture sudah dipakai, jadi migrasi
  sintetis untuk uji bisa dibuat di sana).

## Rencana
1. **Penanda contract**: direktif `-- dbtools:contract <alasan>` (mengikuti pola destruktif). Berkas
   bertanda ini **dilewati** oleh jalur expand (`--up`) dan hanya diterapkan oleh `--contract`.
2. **Urutan**: `--contract` menolak berjalan bila masih ada migrasi expand yang *pending* (contract
   harus datang setelah expand), dan tidak pernah menerapkan berkas tanpa penanda.
3. **`--down [N]`**: butuh berkas pasangan eksplisit `NNNN_nama.down.sql`. Menolak (kode 3) bila
   pasangannya tidak ada, bila migrasi belum diterapkan, atau bila N tidak diberikan. Setelah
   rollback, baris migrasi dihapus supaya `status` mencerminkan kenyataan (perilaku ini dicatat di
   runbook — bukan diam-diam).
4. `ops/scripts/migrate.sh` meneruskan `--contract`/`--down` (tetap wajib `--yes`).
5. Test di `tools/dbtools/tests/`: expand melewati berkas contract; `--contract` menerapkannya;
   `--contract` menolak bila expand masih pending; `--down` menolak tanpa pasangan; `--down`
   mengembalikan keadaan (fixture sintetis, bukan migrasi nyata).
6. Docs: `docs/runbooks/` (prosedur + peringatan "contract/`--down` bukan jalur rutin"), OPEN_ITEMS
   O-048 ditutup, `docs/DECISIONS.md` untuk konvensi penanda.
