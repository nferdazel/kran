# T-156 — Visual regression di Linux sebagai gate

Status: **DONE (31 Okt 2026)**. Rujukan: O-022, D-177.

## Masalah

Spec §15.8 meminta visual regression, dan O-022 mencatat penghalangnya: screenshot bergantung pada
rendering font/antialiasing OS, jadi baseline dari macOS tidak akan cocok di runner Linux.

## Keputusan (D-177)

- `apps/web/tests/e2e/visual.spec.ts` mengambil empat layar deterministik dari seed dev
  (halaman masuk dan buku besar × tema terang/gelap), dengan bagian yang berubah sendiri (tanggal
  buku) di-mask.
- Test **melewati diri sendiri di luar Linux**; gate-nya berjalan lewat `./task e2e` di job
  `web-e2e` (ubuntu-24.04), jadi macOS tidak pernah menghasilkan baseline yang tidak bisa dipakai.
- Baseline dihasilkan di runner yang sama oleh `.github/workflows/visual-baseline.yml`
  (`workflow_dispatch`, input `update`), lalu di-commit ke `visual.spec.ts-snapshots/`.
  Tanpa input `update`, workflow membandingkan — bukti bahwa baseline reproducible, bukan sekadar
  ditulis ulang.
- Ambang diff `maxDiffPixelRatio: 0.01`; animasi dimatikan dan caret disembunyikan supaya hasil
  tidak bergantung waktu.

## Bukti

- Baseline Linux dihasilkan run 41219502893 dan **cocok** pada run banding 41220380661 (job sama,
  tanpa `--update-snapshots`, `./task e2e`-setara) — hijau.
- Lokal (macOS): 4 test di-skip; `./task e2e` 63 lulus / 4 skip di DB segar, `lint-web` dan
  `check-fast` hijau.
- Batas: layar baru tidak otomatis punya baseline — menambah screenshot berarti menjalankan workflow
  dengan input `update`, meninjau artefak, lalu commit hasilnya.
