# T-164 — Pencairan pinjaman + jurnal piutang / simpanan

**Status**: DONE (1 Nov 2026) · **Keputusan**: D-182 (jalur dana + jenis subledger) ·
**Deps**: T-163

## Scope

1. **Domain**: `addMonthsIso` (tanggal jatuh tempo pertama dari tanggal buku, penjepitan akhir
   bulan) tetap satu aturan dengan `buildSchedule`; `TransactionType.ttLoanDisbursement` di
   `deposit/domain/transaction.nim` beserta arah saldo (`+`, `kind: LOAN`) — bukan `CASH_DEPOSIT`.
2. **Repositori**: `insertInstallment`, `installmentCountOf`, `insertBalance`, `markDisbursed`
   (`APPROVED → ACTIVE`, `false` = kalah balapan).
3. **Migrasi**: `deposit/0082` (CHECK `tx_type` diganti, pola `0074`), `ledger/0083` (rule
   `LoanDisbursed` = D 110 / K 201), `platform/0084` (izin `lending.loan.disburse` untuk
   `lending_maker` + `platform_admin`).
4. **HTTP** `POST /api/v1/lending/loans/{loanId}/disburse`:
   - `Idempotency-Key` wajib; replay kunci + isi sama → `200` + `Idempotent-Replayed`, bukan
     pencairan kedua;
   - baris pinjaman dikunci `FOR UPDATE`; `APPLIED` → `409 not_approved`, `ACTIVE` →
     `409 already_disbursed`;
   - rekening tujuan wajib milik peminjam, se-cabang, `ACTIVE`, punya baris saldo;
   - satu transaksi DB: jadwal angsuran, jurnal dari `posting_rule`, subledger
     `LOAN_DISBURSEMENT`, saldo rekening, status `ACTIVE`, audit `lending.loan.disburse`, event
     `LoanDisbursed`.
5. **Rekonsiliasi + rekening koran**: tanda `LOAN_DISBURSEMENT` = `+1` di `reconcile_repo`; jenis
   baru muncul sebagai `kind: LOAN` di kontrak + label web (id/en).

## Non-goals (sengaja)

- **Pencairan tunai langsung** — tidak bisa dibangun tanpa mengubah invarian kas penutupan sesi
  (`teller.cash_movement.transaction_id` wajib menunjuk `deposit.transaction`, yang wajib punya
  rekening simpanan). D-182 mencatat alasannya; tunai tetap lewat penarikan teller.
- Angsuran/pembayaran (T-165), kolektibilitas (T-166), PPAP (T-167), daftar/baca pinjaman (T-169).
- Pembatalan pencairan: koreksi memakai jurnal pembalik, belum ada endpoint-nya.

## Kriteria selesai

- `itapi_lending` (suite pencairan): 200 + jadwal 12 baris dengan `Σ pokok` tepat + jurnal
  `110:DEBIT,201:CREDIT` seimbang + subledger `LOAN_DISBURSEMENT` + saldo rekening bertambah +
  audit + `LoanDisbursed`; replay idempoten tidak menggandakan; pencairan kedua `409
  already_disbursed`; belum disetujui `409 not_approved`; rekening anggota lain `409
  account_party_mismatch`; tanpa kunci / `accountId` bukan uuid → 400.
- `itreconcile`: baris `LOAN_DISBURSEMENT` menambah saldo yang diharapkan (`+25,00`), bukan nol
  atau diabaikan.
- `tcontract`: `disburseLoan` memakai `IdempotencyKey`, punya `409`, dan mendeklarasikan header
  `Idempotent-Replayed` di `200`.
- `./task check-fast`, `./task build`, `./task openapi` hijau; `./task test` + `./task e2e` hijau.
