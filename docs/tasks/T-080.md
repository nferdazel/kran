# T-080 — O-089: tutup periode tidak bisa ditembus jurnal bersamaan

**Status:** DONE (reviewer APPROVE, ci hijau)
**Sumber:** O-089 (`docs/OPEN_ITEMS.md`), temuan pre-existing T-072/T-073.

## Scope

Trigger `ledger.assert_journal_period_open()` hanya **membaca** status periode. Bila sesi A
menutup periode (belum `COMMIT`) dan sesi B memposting jurnal pada tanggal itu, B melihat versi
lama `OPEN` → insert berhasil, lalu A commit; jurnal berakhir di periode `CLOSED`.

Perbaikan: `SELECT ... FOR SHARE` pada baris periode di trigger. B menunggu lock baris yang
dipegang `UPDATE` A, lalu mengevaluasi versi **setelah** commit (`CLOSED`) → ditolak. Arah
sebaliknya aman: bila jurnal memegang lock lebih dulu, penutupan menunggu jurnal commit, dan
jurnal tetap tercatat pada periode `OPEN`.

Tidak ada perubahan API, model, atau parameter. Hanya fungsi trigger (expand-only, `CREATE OR
REPLACE`).

## Catatan risiko

- Lock baris periode dipegang sampai transaksi jurnal commit → satu lock per jurnal, memperbesar
  peluang antre pada volume tinggi. Untuk pilot (D-072: tanpa partisi, volume kecil) memadai;
  bila throughput jadi masalah, alternatifnya advisory lock per periode atau penutupan lewat
  `daycloser` yang sudah memegang lock eksklusif (Fase 5).
- Penutupan periode kini juga menunggu jurnal yang sedang berjalan (bukan hanya sebaliknya).
  Ini diinginkan: jurnal yang sudah mulai sebelum penutupan tetap sah pada periode OPEN.
