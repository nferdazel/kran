# T-061 — jalur DB tidak punya batas waktu klien (T-044 H1)

Status: **DONE** (19 Okt 2026). Prioritas: P1 (produksi bisa menggantung tanpa batas).
Sumber: `docs/tasks/T-044.md` bagian H1 (terbukti langsung dengan eksperimen black-hole).

## Kenapa

`shared/platform-lib/db/pool.nim` membuat koneksi lewat `pqsetdbLogin`, yang **tidak menerima**
`connect_timeout`. `statement_timeout` berlaku server-side (baru setelah koneksi hidup), jadi peer
yang menerima TCP tetapi diam membuat `acquire`/`dbtools` menunggu **tanpa batas**. Konsekuensi
nyata: `kran-api` (termasuk `/readyz` dan drain) bisa menggantung saat tunnel/jaringan membeku tanpa
RST — bukan gagal cepat.

## Rencana

1. **Koneksi** (`pool.nim`): ganti `pqsetdbLogin` → `pqconnectdb(conninfo)`, sertakan
   `connect_timeout` dari konfigurasi baru `KRAN_DB_CONNECT_TIMEOUT_MS` (default 5000; libpq
   menafsirkan < 2 s sebagai 2 s) + `keepalives=1 keepalives_idle=5 keepalives_interval=5
   keepalives_count=2` supaya koneksi idle yang membeku terdeteksi kernel (±15 s), bukan menunggu
   berjam-jam. Nilai di-*quote* gaya conninfo (escape `\` dan `'`).
2. **Konfigurasi** (`config.nim`): field `connectTimeoutMs`, konstanta default, parser env, dan
   `knownEnvKeys` (tanpa itu env tidak terbaca lewat tabel env — catatan reviewer T-060).
3. **Test**: `shared/platform-lib/tests/tdbconnect.nim` — listener yang `accept`-tapi-diam
   (black-hole) harus menghasilkan `PoolError < 10 s`; kontrol port tertutup tetap gagal cepat;
   `connInfo` memuat `connect_timeout` dan meng-escape nilai. `tconfig` diperluas.

## Kriteria selesai

- `./task test tdbconnect` hijau, termasuk kasus black-hole (tanpa fix: menggantung, bukan gagal).
- `./task test tconfig` hijau; `./task test itpool` + `itapi` (butuh DB) hijau.
- `./task check` exit 0; tidak ada env baru yang tidak terdaftar.
- Batas jujur: koneksi **yang sudah hidup** lalu membeku di tengah query masih bergantung pada TCP
  keepalive (terbatas ±15 s), bukan deadline per-query. Deadline per-query butuh libpq nonblocking +
  `PQsocket` dan dicatat sebagai sisa, bukan diklaim selesai.

## Risiko

- Mengubah jalur koneksi produksi: bentuk pesan `PoolError` dipertahankan (`gagal menyambung ke …`).
- Nilai password dengan spasi/kutip/backslash harus tetap tersambung → diuji lewat escape conninfo
  + test integrasi pool yang sudah ada.
