# T-122 — Plafon nominal kas teller & vault (O-099/K-5)

Status: **DONE** (24 Okt 2026) — D-133. Angka = kebijakan pilot, `NEEDS-COMPLIANCE-REVIEW`.

## Scope

Sebelumnya jalur kas menerima nominal berapa pun selama saldo cukup (O-099). Pemilik menyetujui
usulan SME akuntansi (`docs/proposals/t-118-sme-accounting.md` §1): empat plafon sebagai parameter.

1. **Parameter** (`modules/teller/seeds/params.yaml`, tipe `money`, scope `[GLOBAL, INSTITUTION]`,
   `sensitivity: NORMAL`, `provenance.class: kebijakan` + `NEEDS-COMPLIANCE-REVIEW`):
   `teller.cash.limit_opening_float` 2.000.000; `teller.cash.limit_deposit` 10.000.000;
   `teller.cash.limit_withdrawal` 5.000.000; `teller.vault.limit_topup_per_request` 25.000.000.
2. **Pembacaan bersama** `apps/api/src/cash_limit.nim`: `cashLimit(db, key, asOf)` (scope institusi,
   tanggal bisnis) → `CashLimitConfigError` bila hilang/rusak; `exceedsLimit` ketat `>`.
3. **Pengecekan di handler** (domain tetap murni), sebelum saldo/sesi/jurnal disentuh:
   buka sesi (`handlers_teller_sessions.nim`), setor/tarik (`handlers_teller.nim`), submit top-up
   (`handlers_teller_vault.nim`). Pelanggaran = **409** `cash_limit_exceeded` /
   `topup_exceeds_limit`; parameter hilang = **500** (fail-closed).
4. **Kontrak**: deskripsi ketiga operasi menyebut `params.reason` baru; klien TS diregenerasi.
   Deskripsi buka sesi yang masih menyatakan "tidak ada jurnal GL" diperbaiki (T-118 sudah berjurnal).
