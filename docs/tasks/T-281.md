# T-281 - Typed OpenAPI timestamps

Phase: P0a · Size: S · Risk: standard (general) · Status: DONE

## Scope

Give every timestamp property in the contract a real type: `format: date-time` for ISO-8601
instants, `format: date` for date-only values, and keep nullable properties nullable
(`type: ["string", "null"]` plus the format, not a bare `type: string`). Write the list of touched
properties into this file as the work is done, so the count is checkable: 35 unformatted today, 0
expected after.

timestamps (money strings, ids), and adding new spectral rules beyond what this change needs.

`itapi_auth` rebuilds the database itself: it runs `resetTestSchemas` (drops every module schema)
then re-applies migrations and seeds (`apps/api/tests/itapi_auth.nim:73`). So it is only meaningful
when no other worktree is touching `kran_dev` at the same moment. My first run was green. Two later
runs failed with `relation "platform.outbox" does not exist` / `relation "platform.business_date"
does not exist` and 401s, and while they ran `ps` showed `cbs-wt-gate` and `cbs` compiling
`itapi_teardown` and `itapi_product` against the same database, whose `resetTestSchemas` drops the
schemas mid-run. That is contention, not this change: the diff is one YAML file plus generated
types, and the API server never reads the contract at runtime.

### Generated client: comment-only, zero type changes

`./task openapi-gen` after the contract change rewrites `schema.d.ts` by **121 insertions / 26
deletions**, and every one of them is a JSDoc line. `openapi-typescript` 7.13.0 emits
`/** Format: date */` and `/** Format: date-time */` for formatted properties, and expands an
existing one-line `/** @description … */` into a block when a format joins it. The TypeScript type
stays `string` in every case, as the task predicted; the file is **not** byte-identical.

Proof that no type moved: strip `/**`, `*` and `*/` lines from both versions and diff the rest.

```
before code lines: 5518   after code lines: 5518
identical code (comments removed): True
changed lines that are not comments: 0
```

The two existing `format: date-time` fields (`computedAt`, `occurredAt`) already looked exactly like
the new ones, so this is the generator's normal output for a formatted field, not a side effect of
this change. No `apps/web` type was adjusted.

### Seeded violation (acceptance 2): spectral does not catch it

`AuditItem.recordedAt` had its `format: date-time` removed and the client regenerated, so the
"client in sync" check could not mask the result:

```
$ ./task openapi
No results with a severity of 'warn' or higher found!
   ok: contract passed lint (fail-severity warn)
   ok: TS client in sync with contract
   ok: API client package passed typecheck
EXIT 0
```

`spectral:oas` has no rule requiring `format` on a date-like string, so a timestamp can regress to a
bare `type: string` and the gate stays green. Per the task's own instruction this is recorded as an
open item rather than patched with a new rule invented here (adding rules is out of scope). The
state was restored and `./task openapi` re-run green afterwards.

Open item for P0a follow-up: a spectral rule (or a small contract check) that fails when a property
whose name matches `(At|On|Due|Date)$` or whose description says ISO-8601 carries no `format`.
