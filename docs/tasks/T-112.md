## Desain test

Berkas: `apps/api/tests/itapi_teller.nim`, suite `deposit: statement subledger (T-094b)`.

Test baru: *"di atas batas 500 gabungan kas + PB (tiap sumber < 501) → 400, bukan potong diam-diam"*.

1. **500 baris (tepat batas) → 200.** Tanam 250 transaksi tunai + 250 PB untuk satu rekening
   khusus (`freshAccount()`), lalu `GET .../statement?from=&to=` `BusinessDate..BusinessDate`.
   Assert `200`, `checkJson` kontrak, `rows.len == 500`. Tiap kueri sumber hanya mengembalikan 250
   (< `probeLimit` 501), jadi 200 membuktikan batas dihitung dari gabungan.
2. **501 baris (tiap sumber masih < 501) → 400.** Tambah **1** transaksi tunai (kas 251 + PB 250 =
   501 > 500). Assert `400`, `checkProblem` kontrak problem+json, `detail` memuat `"500"`, dan
   `body` **tidak** membawa `rows` (tidak ada respons separuh).

Catatan pembeda error 400 (baca kode, jangan mengarang): `handleGetAccountStatement` memetakan
kelebihan baris ke `req.respondProblem(pkBadRequest, "Bad Request", problem)` **tanpa**
`params.reason`. Jadi discriminatornya adalah `detail` (`"rentang tanggal melebihi 500 baris;
persempit rentang"`), bukan `params.reason`. Test mengassert `detail`, bukan reason yang tidak ada.

### Penyiapan data efisien

Helper `seedStatementBulk(tag, accountId, otherId, cashCount, transferCount)` menanam baris
**langsung lewat SQL** dalam **satu** `execScript` (satu transaksi implisit `pqexec`) — bukan
ratusan request HTTP:

- `ledger.journal` + `ledger.journal_line` seimbang (2 baris, akun `201`, `BusinessDate` di periode
  OPEN) per baris statement, karena `deposit.transaction.journal_id`/`deposit.transfer.journal_id`
  **NOT NULL + UNIQUE** dan FK ke `ledger.journal`.
- `idempotency_key` jurnal diberi prefiks `t112-<tag>-cash-…`/`t112-<tag>-pb-…` supaya antar-batch
  tidak bentrok; `tag` berbeda per pemanggilan.
- Rekening memakai `freshAccount()` **khusus test ini** (semua test memakai `BusinessDate`, jadi
  berbagi rekening akan membocorkan baris ke statement test lain).
- 2 rekening fixture dipakai (account + tujuan PB); total pemakaian fixture tetap < `AccountFixtures`
  (48).
