# T-136 — Gate pra/pasca-tutup

Status: **selesai** 28 Okt 2026. Bagian dari Fase 3 (spec §11.5 langkah 2 & 5, §11.6).
Prasyarat: T-134 (kerangka), T-135 (siklus business date).

## 1. Masalah

Kerangka `daycloser` menjalankan task, tetapi belum ada satu pun **gate**: run bisa ditutup tanpa
memeriksa bahwa kas teller beres, tidak ada pengajuan menggantung, tidak ada saldo di akun selisih,
TB seimbang, dan subledger simpanan cocok dengan GL. Spec §11.5 menempatkan pemeriksaan itu sebagai
langkah tersendiri (precheck sebelum freeze, postcheck sebelum seal).

Selain itu kegagalan gate sekarang berujung `FAILED` — sama dengan task yang crash. Operator tidak
bisa membedakan "sistem rusak" dari "buku belum layak ditutup", padahal tindakannya berbeda.

## 2. Lingkup

**PRECHECK (sebelum freeze)**

| Task | Aturan | Bukti (metrics) |
|---|---|---|
| `teller.sessions_closed` | tidak ada sesi `OPEN` dengan `business_date <= tanggal tutup`; tidak ada sesi `CLOSED` pada tanggal itu dengan `variance <> 0` | jumlah sesi terbuka, jumlah sesi selisih, daftar sesi bermasalah (maks 20) |
| `teller.pending_approvals` | tidak ada `teller.vault_topup_request` berstatus `PENDING` | jumlah per jenis |
| `ledger.suspense_zero` | saldo akun pada parameter `daycloser.precheck.suspense_accounts` = 0 | saldo per akun |

**POSTCHECK (sebelum seal)**

| Task | Aturan | Bukti (metrics) |
|---|---|---|
| `ledger.trial_balance` | Σ debit = Σ kredit kumulatif s.d. tanggal tutup | total debit, total kredit, selisih, jumlah akun |
| `ledger.subledger_vs_gl` | Σ `deposit.account_balance` = saldo akun GL pada `daycloser.postcheck.subledger_gl_accounts` | saldo subledger, saldo GL, selisih, jumlah rekening |
| `ledger.no_late_postings` | tidak ada jurnal bertanggal **tanggal tutup** dengan `recorded_at` setelah freeze (`business_date.updated_at` saat `CLOSING`) — menutup celah TOCTOU gerbang HTTP (review T-135) | jumlah jurnal terlambat + id (maks 20) |

**State `BLOCKED`**: kegagalan task **gate** (`tkPreCheck`/`tkPostCheck`) yang kritis menghasilkan
run `BLOCKED`, bukan `FAILED`. `FAILED` tetap untuk kegagalan task proses/laporan. Keduanya bisa
di-`resume`; bedanya hanya pesan operator dan arti di UI (menyusul T-139).

**Parameter baru** (bukan magic number):

- `daycloser.precheck.suspense_accounts` (json array, default `["101.9"]`)
- `daycloser.postcheck.subledger_gl_accounts` (json array, default `["201", "202"]`)

**Di luar lingkup**: rekonsiliasi per rekening (`accountBalanceMismatches` sudah ada, dijadwalkan
sebagai task T-137), akun antar-kantor (belum ada di COA — dicatat sebagai batas), UI (T-139).

## 5. Rancangan query (draf, disesuaikan saat implementasi)

Semua query **baca saja** dan memakai indeks yang ada; tidak ada tabel baru di T-136.

```sql
-- teller.sessions_closed
SELECT count(*) FILTER (WHERE status = 'OPEN')                          AS open_sessions,
       count(*) FILTER (WHERE status = 'CLOSED' AND variance <> 0)      AS unbalanced,
       count(*)                                                         AS total
  FROM teller.teller_session
 WHERE business_date <= ?::date;

-- platform.pending_approvals
SELECT count(*) FROM teller.vault_topup_request WHERE status = 'PENDING';

-- ledger.suspense_zero (akun dari parameter)
SELECT account_code, debit_total - credit_total AS balance
  FROM ledger.journal_line l JOIN ledger.journal j USING (journal_id)
 WHERE l.gl_account = ANY(?::text[]) AND j.business_date <= ?::date
 GROUP BY account_code;   -- saldo akun aset: debit - kredit

-- ledger.no_late_postings (TOCTOU)
SELECT count(*)
  FROM ledger.journal j
 WHERE j.business_date = ?::date
   AND j.recorded_at > (SELECT updated_at FROM platform.business_date
                         WHERE scope_type = 'INSTITUTION' AND scope_id IS NULL);

-- ledger.trial_balance (lewat balancesFromLedger(startsOn, tanggalTutup))
--   Σ closingDebit == Σ closingCredit; selisih dilaporkan dalam Money, bukan float.

-- ledger.subledger_vs_gl
SELECT (SELECT coalesce(sum(b.balance), 0) FROM deposit.account_balance b)::text AS subledger,
       (SELECT coalesce(sum(l.debit - l.credit), 0) FROM ledger.journal_line l
          JOIN ledger.journal j USING (journal_id)
         WHERE l.gl_account = ANY(?::text[]) AND j.business_date <= ?::date)::text AS gl;
```

Catatan implementasi:

- `suspense_zero` memakai saldo normal akun (`debit - kredit`) karena yang diatur parameter adalah
  akun **aset** (kas/selisih). Bila kelak akun suspense berupa kewajiban, gate harus membaca
  `normal_balance` dari COA — bukan menebak dari kode akun.
- Gate yang membaca akun dari parameter mendaftarkannya di `requiredParams` (tercatat di
  `daycloser.task_registry` dan rencana run). Nilai yang benar-benar dipakai dibuktikan oleh
  `task.metrics` (daftar akun + saldo), bukan oleh snapshot parameter: `param_snapshot` run hanya
  memuat `Config` (`chunk_size`, `max_attempts`, `retry_backoff_seconds`). Parameter hilang/rusak =
  gate **gagal**.

## 7. Keputusan (detail: D-150)

1. **Gate gagal = `BLOCKED`, task proses gagal = `FAILED`.** Bagi operator keduanya berbeda:
   `BLOCKED` = buku belum layak ditutup (perbaiki keadaan), `FAILED` = eksekusi rusak.
2. **Gate hanya membaca.** Tidak ada penulisan koreksi otomatis; selisih adalah temuan untuk
   diselidiki, bukan sesuatu yang "dirapikan" oleh penutup.
3. **Gate PRECHECK berjalan sebelum freeze.** Karena itu kegagalan gate pra-tutup membiarkan
   tanggal `OPEN` (institusi masih boleh melayani); yang menahan adalah run `BLOCKED` itu sendiri
   dan gate deploy tidak ikut menahan. Kegagalan gate pasca-tutup meninggalkan tanggal `CLOSING`.
4. **Bukti disimpan di `daycloser.task.metrics`, termasuk saat gate gagal.** `TaskError` membawa
   `metrics` supaya angka penyebab penolakan tidak hilang bersama hasil yang gagal.
5. **Akun dari parameter, bukan literal.** `101.9` (selisih kas) dan `201`/`202` (kewajiban
   simpanan) adalah nilai awal parameter, dapat diubah lewat maker-checker.
6. **Saldo kumulatif sampai tanggal tutup**, dinilai menurut `account_type` COA — bukan tebakan
   dari kode akun, sehingga akun suspense berkewajiban kelak tidak terbaca dengan tanda salah.
7. **Jurnal terlambat dideteksi, bukan dicegah.** Gerbang HTTP adalah cek-lalu-jalan (TOCTOU dari
   review T-135); gate membandingkan `journal.recorded_at` dengan `business_date.updated_at`
   berpresisi mikrodetik. Perbaikan penuh (drain) tetap pekerjaan Fase 9.
8. **Gate didaftarkan lewat proc `gateTask(spec, pool)`.** Closure yang dibuat di badan loop
   menangkap satu variabel bersama — sempat membuat semua gate menjalankan pemeriksaan terakhir
   (tertangkap integration test, bukan produksi).
