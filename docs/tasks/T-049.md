# T-049 — O-035: validasi bentuk input parameter sebelum menyentuh DB

Status: **DONE — tanpa perubahan kode; sudah dicakup lebih dulu oleh T-022** (dikonfirmasi
16 Okt 2026).
Prioritas: P2.

## Kenapa

Baris register `O-035` menyatakan beberapa kesalahan input klien berakhir 500 (bukan 400/404):
tanggal non-ISO lewat cast `?::date`, `scopeId` terisi pada scope `GLOBAL`, dan `paramValueId`
non-uuid. Tugas ini memeriksa apakah kasus-kasus itu masih terbuka sebelum menyentuh kode.

## Temuan (recon, jangan menebak)

Kasus-kasus yang disebut baris `O-035` **sudah tertutup**, dan bukan oleh task ini melainkan oleh
**T-022** ("Validasi bentuk permintaan parameter (O-035)", `docs/BACKLOG.md` baris Fase 0, DONE) —
baris register-nya tertinggal `READY`. Pola yang sama seperti O-036/T-047.

Per-kasus:

| Kasus (dari O-035) | Penjagaan kode | Bukti uji |
|---|---|---|
| Tanggal non-ISO / tak ada di kalender | `http_util.nim:51` `isIsoDate` (memeriksa rentang & jumlah hari, mis. `2026-02-31` ditolak) dipanggil `handlers_param.nim:117`/`:122` **sebelum** `withDbTx` | `itapi_auth.nim:437` — "efektif bukan tanggal" (`2026-13-45`), "tanggal tidak ada di kalender" (`2026-02-31`), "effectiveTo bukan tanggal" (`besok`) → 400 |
| Periode tidak wajar | `handlers_param.nim:126` (`effectiveTo <= effectiveFrom`) | idem — "periode terbalik", "periode kosong (from = to)" → 400 |
| `scopeId` terisi pada scope `GLOBAL` | `handlers_param.nim:139` | idem — "scopeId pada GLOBAL" → 400 |
| Kombinasi scope (non-GLOBAL tanpa id; scope tak dikenal) | `handlers_param.nim:132` (`parseScopeType`) + `:142` | idem — "scope tidak dikenal" (`BOGUS`), "scope non-GLOBAL tanpa scopeId" → 400 |
| `paramValueId` non-uuid (approve) | `handlers_param.nim:198` `parseId` → 404 (sebelum `?::uuid`) | `itapi_auth.nim:466` — "paramValueId bukan UUID dijawab 404, bukan 500" |

Setiap kasus diperiksa **sebelum** `withDbTx`, jadi tidak ada query DB untuk input tak sah; semuanya
dibalas amplop `problem+json` (di-assert `checkProblem(...)`). Uji kontrol "pengajuan dengan tanggal &
scope yang sah tetap 201" (`itapi_auth.nim:473`) memastikan validasi tidak terlalu ketat.

Kasus lain yang ditemukan di luar daftar O-035 (sudah benar, dicatat saja):

- `GET /api/v1/params?status=<garbage>` → 400 (`handlers_param.nim:56`).
- `GET /api/v1/audit?limit=<garbage|0|>max>` → 400 (`handlers_audit.nim:49`).
- Jalur lintas-parameter (temuan ronde 5 di baris O-035) memakai `effectiveFrom`/`effectiveTo` yang
  sudah tervalidasi; `asOf`-nya dari jam server (`businessDateIso`), bukan input klien.
