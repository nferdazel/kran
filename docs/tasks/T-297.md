## Scope

1. `deploy-vps.sh`, build branch: capture the `:local` image ID before tagging. If the recorded
   `OLD_PREV_IMAGE_ID` equals it (both tags were on one image, so the retag was a no-op), clear it
   so `prune_previous_image` does not delete the only holder of `:prev`. Set
   `PREV_TARGET_REQUIRED=1` whenever a `:local` image existed before the build.
2. `deploy-vps.sh`, health gate: with `PREV_TARGET_REQUIRED=1`, a green `/readyz` is not enough —
   `:prev` must exist and its image ID must differ from `:local`. A host that never built has
   nothing to roll back to and is exempt. Failure follows the existing auto-rollback path.
3. `ops/systemd/*.container`: fold the four host-only settings into the repo so `sync_units` stops
   stripping them — `OnFailure=alert@%N.service` (`[Unit]`), `PidsLimit=256`, `ReadOnly=true`,
   `Tmpfs=/tmp:size=64m` (`[Container]`). The alert template itself stays host-owned; the repo
   unit records that dependency in a comment.
4. `docs/OPERATIONS.md`: step 8 and 11 of §1.1 state the two invariants; new §1.6 lists the unit
   hardening and why it lives in the repo.

Deliberately not in scope: `rollback.sh` itself (its `:prev` precondition is correct), shipping
`alert@.service` or `alert-notify.sh` in this repo, and re-implementing the prune as an image list
scan.

## Acceptance

1. Same-image deploy (both tags on one image before build) leaves `:prev` pointing at the old
   image and prunes nothing. On the parent commit the stub run deletes that image.
2. Normal rotation still prunes exactly the superseded `:prev` image and keeps `:prev` != `:local`.
3. A build deploy on a host with no `:prev` fails the gate instead of reporting success.
4. A host that never built is not blocked by the rollback-target requirement.
5. `bash -n` and `shellcheck -S warning` pass for `ops/scripts/deploy-vps.sh`; repo unit files match
   the live qouver1 units on every directive except comment text and the position of
   `OnFailure=` inside `[Unit]` (semantically identical).
