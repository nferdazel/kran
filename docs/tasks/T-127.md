# T-127 — `resetTestSchemas` menolak database non-dev

Status: **selesai** 24 Okt 2026. Sumber: audit 24 Okt 2026 BLK-2.

## Masalah

`resetTestSchemas` (`tools/dbtools/lib.nim`) menjalankan `DROP SCHEMA … CASCADE` untuk semua modul
saat integration test dimuat. Tidak ada pemeriksaan nama database, padahal `seed --dev` sudah dijaga
`devSeedDbAllowed` (`_dev`/`_test`) sejak O-062. Satu `KRAN_DATABASE_URL` yang masih menunjuk
database pilot = seluruh skema pilot hilang sebelum test pertama selesai.

## Yang diubah

- `testDbNameAllowed(name)` menjadi **satu-satunya** definisi "database dev/test"; `devSeedDbAllowed`
  memakainya (tidak ada dua aturan yang bisa berbeda).
- `resetTestSchemas` membaca `SELECT current_database()` dari server — bukan dari env pemanggil —
  lalu menolak dengan `ValueError` yang menyebut nama DB bila tidak berakhiran `_dev`/`_test`.
  Memeriksa dari server membuat penjaga tidak bisa diakali dengan mengubah URL saja.

## Bukti

- `./task test tdbtools` → 3 suite `[OK]`, termasuk kasus `testDbNameAllowed` untuk `kran_dev`,
  `kran_test`, `cbs_dev`, `kran`, `kran_prod`, `kran_devx`, `""`.
- `./task test itplatform` → hijau pada `kran_dev` (penjaga mengizinkan DB dev, reset tetap berjalan).
- Penolakan tidak diuji terhadap DB non-dev sungguhan (tidak ada DB bernama lain di mesin ini);
  predikatnya diuji unit, sedangkan sumber namanya `current_database()`.
