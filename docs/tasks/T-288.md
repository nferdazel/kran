## Scope

Optional props on the existing component: `density` (`default` 40 / `compact` 36), `stickyHeader`,
`totals` (a row rendered in `<tfoot>`, bold, with a rule above), `rowLines` (primary line 13/600 and a
second 11 muted line) and `selectedKeys` with `onSelect` for row selection.

Selection rules: selected row gets a 2px inset accent bar on the left, `--surface-2` fill and
`aria-selected`; hover is `--surface-2` only; selection is keyed by `rowKey`, so it survives sorting
and pagination because the caller owns the key set, not the row index. `aria-sort` stays on the
active header only, one direction indicator at 12px.

Deliberately not in scope: interactive sort buttons (today `sort` only states the current order), the
period control question, column resizing, and any screen's column set.

## Acceptance

New cases in `packages/ui/tests/components.test.ts` fail on the parent commit because the props do
not exist:

1. `density="compact"` renders the 36 row class, no `density` renders 40.
2. `totals` renders a `<tfoot>` row whose first cell is `<th scope="row">`, not a `<td>`.
3. `selectedKeys=["A"]` marks exactly that row `aria-selected="true"` and gives it the selection
   class; a second row is `aria-selected="false"` or has no attribute, never `"true"`.
4. Reordering `rows` while keeping the same `selectedKeys` keeps the same row selected - the test
   asserts by `rowKey`, not by index.
5. `rowLines` renders both lines for a row that provides them, and only one line for a row that
   does not (no empty second line).
6. The scroll wrapper still renders exactly one `tabindex="0"` and one `role="region"`.

At 200% zoom the table scrolls inside its own box with no card conversion; that is a manual check in
both themes, recorded in Evidence.
