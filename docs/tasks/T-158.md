# T-158 — `./task release` + workflow rilis

**Status**: DONE (1 Nov 2026) · **Keputusan**: D-178 · **Deps**: T-157

## Kenapa

Rilis sebelumnya tidak punya bentuk: tidak ada tag versi, tidak ada catatan perubahan, dan tidak ada
definisi "apa yang naik pada rilis ini". Model `majadu` (T-033 di sana) sudah terbukti; kran
mengadopsinya **dan** menutup celah `VERSION == tag` yang di sana belum diperiksa.

## Scope

- `tools/gen-changelog.sh`: satu blok Keep a Changelog dari Conventional Commits
  (`feat` → Added, `fix` → Fixed, `perf`/`refactor` → Changed, `ops`/`ci`/`deploy` → Operations),
  `chore: release*` dilewati, scope `web`/`ui` tidak dipajang.
- `cmd_release` di `./task`: tree bersih → bump (diturunkan atau dipaksa) → naikkan `VERSION` +
  manifest → `gen-version.sh` → changelog → gate `check-fast` + `build` (+ `version-check`) →
  commit `chore: release vX.Y.Z` → tag anotasi → `push --follow-tags` → `gh release`.
  `--skip-check` dicatat di catatan rilis; `--no-push` untuk latihan.
- `.github/workflows/release.yml`: trigger `tags: v*`, `timeout-minutes: 15`, memverifikasi
  `VERSION` == tag == manifest == berkas generated, lalu membuat release idempoten; hanya tag
  terbaru `--latest`.

## Batas

- Tidak ada DCO (`-s`): repo ini tidak memakai alur itu.
- Tag bukan pemicu deploy (D-013); deploy tetap dari push ke `main`.
- Gate rilis lokal bukan `./task ci` penuh (e2e butuh stack khusus); jaminan menyeluruh dari CI,
  dan `deploy-vps.sh` menunggu CI (T-159).

## Bukti

`sh -n task`, `bash -n tools/gen-changelog.sh`; `version-check` hijau; `release.yml` dibuat dengan
`timeout-minutes: 15` dan nilai konteks lewat `env:` (bukan interpolasi shell).
