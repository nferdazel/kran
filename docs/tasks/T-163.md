# T-163 — Pengajuan & persetujuan pinjaman (maker-checker)

**Status**: DONE (1 Nov 2026) · **Keputusan**: D-180, D-099 (pola maker-checker produk) ·
**Deps**: T-162

## Scope

1. **Domain** (`modules/lending/domain/loan.nim`): `canApprove(status)` (hanya `APPLIED`) dan
   `assertDistinctActors(maker, checker)` — empat mata sebagai aturan domain, bukan hanya CHECK DB.
2. **Repositori** (`modules/lending/infrastructure/loan_repo.nim`): `productVersionById` (atribut +
   status), `insertLoan`, `loanById(forUpdate)`, `approveLoan` (`UPDATE … WHERE status='APPLIED'`
   → `false` = kalah balapan, bukan galat).
3. **Izin** (`modules/platform/migrations/0081_platform_rbac_lending.sql`): `lending.loan.read`,
   `lending.loan.submit`, `lending.loan.approve`; peran sempit `lending_maker`/`lending_checker` +
   baris `role_conflict` (satu orang tidak boleh memegang keduanya); `platform_admin` memegang
   ketiganya (empat mata tetap ditegakkan domain + CHECK).
4. **Parameter** (`lending/seeds/params.yaml`): `lending.loan.max_principal` (plafon pengajuan,
   `komersial-konservatif`, `NEEDS-COMPLIANCE-REVIEW`). Hilang/rusak = galat konfigurasi 500,
   **bukan** plafon tak terbatas.
5. **HTTP** (`apps/api/src/handlers_lending.nim` + `routes.nim` + kontrak):
   - `POST /api/v1/lending/loans` → 201 `APPLIED`; cabang diambil dari data anggota (bukan badan
     permintaan), lalu `authorizedAtBranch`; anggota tidak `ACTIVE` → 409 `party_not_active`;
     versi produk bukan `ACTIVE` → 409 `product_version_not_active`; pokok di atas plafon → 409
     `limit_exceeded` (tepat di plafon diterima).
   - `POST /api/v1/lending/loans/{loanId}/approve` → 200 `APPROVED`; baris dikunci `FOR UPDATE`;
     bukan `APPLIED` → 409 `not_applied`; penyetuju = pengaju → 409 `self_approval`.
   - Audit `lending.loan.submit` / `lending.loan.approve`; event `LoanSubmitted` / `LoanApproved`
     (dedup per pinjaman), semuanya dalam transaksi yang sama dengan penulisan pinjaman.

## Non-goals (sengaja)

- **Pencairan** (uang bergerak, jurnal, jadwal disimpan) = T-164; di sanalah `Idempotency-Key`
  wajib, karena hanya di sana ada mutasi keuangan yang bisa tergandakan.
- **Penolakan pengajuan** (`REJECTED`) belum ada: status di skema hanya
  `APPLIED/APPROVED/ACTIVE/CLOSED/WRITTEN_OFF`, dan menambah status butuh migrasi + aturan siapa
  yang boleh menolak. Dicatat sebagai sisa, bukan dikerjakan setengah.
- **Daftar/baca pinjaman** lewat HTTP dan scoping baca = T-169.
- Pembatalan pengajuan, penomoran pinjaman bisnis, dan kalender hari libur: belum ada.
