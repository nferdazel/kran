## Scope

1. **Ownership is checked before the branch rule.** If the session's `teller_user_id` is not the
   caller, the caller needs `teller.session.read_all` at the session's branch; otherwise 403 with
   reason `session_not_owned`. The owner keeps `teller.session.read`, unchanged, so the cash screen
   needs no new permission to show its own session.
2. **A separate permission, not a widened one.** `teller.session.read` is held by every teller; using
   it for foreign sessions would remove the boundary the finding is about. `read_all` goes to
   `cash_admin` and `platform_admin` only, written as an explicit grant list so a role added later
   does not inherit it by accident.
3. **The route gate accepts either code.** `requireAnyPermission` was extracted from
   `requirePermission` (same DB and must-change-password guards) so a supervisor holding only
   `read_all` is not refused before ownership is even evaluated.

Deliberately not changed: `GET current` (already filters by teller), the close path (already returns
409 `session_not_owned`), and the transaction payload shape.

## Acceptance

A teller holding `teller.session.read` in the branch, but not the owner, gets 403
`session_not_owned`; the owner gets 200; an `read_all` holder in that branch gets 200; an `read_all`
holder in another branch gets 403.
