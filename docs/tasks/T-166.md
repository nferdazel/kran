# T-166 — Task day-close `lending.dpd_regrade`

**Status**: READY (1 Nov 2026) · **Keputusan**: D-180 butir 2+3 (ambang DPD, PPAP menyusul) ·
**Deps**: T-165

## Scope

1. **Domain** (`modules/lending/domain/collectibility.nim`, murni): `daysPastDue(dueOn, businessDate)`
   memakai `businessdate.daysBetween` (tidak ada aritmetika tanggal sendiri), `gradeOf(dpd, bounds)`
   dengan ambang dari parameter, dan tipe `Collectibility` (`COLLECTIBLE`, `SPECIAL_MENTION`,
   `SUBSTANDARD`, `DOUBTFUL`, `LOSS`). DPD dihitung dari **angsuran belum lunas tertua**, bukan dari
   `paid_on`: membayar bunga saja tidak boleh menghapus tunggakan pokok.
2. **Parameter**: `lending.collectibility.dpd_bounds` = `[90, 120, 180]` (sudah ada sejak T-161,
   `NEEDS-COMPLIANCE-REVIEW`). Tidak ada angka ambang di kode; parameter rusak → task gagal dengan
   kode `DAY-4xx`, bukan diam-diam memakai ambang bawaan.
3. **Skema** (`lending/…`): `lending.collectibility_snapshot` (`loan_id`, `business_date`, `dpd`,
   `grade`, `primary key (loan_id, business_date)`) — idempotensi nyata, bukan "sudah jalan berarti
   selesai"; plus kolom `lending.loan.collectibility` sebagai nilai terkini untuk laporan.
4. **Task day-close** (`apps/api/src/daycloser_lending.nim`, terdaftar seperti
   `daycloser_deposit.nim`): `lending.dpd_regrade`, `kind = tkChunked`, chunk dari daftar pinjaman
   `ACTIVE`, ukuran chunk dari `daycloser.chunk_size`. Per chunk: hitung DPD, simpan snapshot
   (`ON CONFLICT DO NOTHING`), perbarui `lending.loan.collectibility`, audit **per chunk**
   (`lending.collectibility.regrade`), dan event `CollectibilityChanged` hanya bila grade berubah.
5. **Idempotensi**: menjalankan task dua kali pada tanggal buku yang sama tidak menambah snapshot
   dan tidak menerbitkan event kedua (dibuktikan test).
