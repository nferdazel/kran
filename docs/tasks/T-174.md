## Scope

Add `apps/api/src` (excluding `/generated/`) to `isScanned`, and give the tool a baseline with the
same semantics as `tools/archcheck/baseline.txt`: a listed finding is accepted, an unlisted one
fails the gate, and a listed finding that no longer occurs also fails ("baseline stale, shrink it").

The rule shape for handlers must be decided explicitly and written into this file before the
baseline is captured, because a handler legitimately holds numbers that are not business values:
HTTP status codes, body-size caps, header lengths, retry-after seconds. Two things are not allowed
as a shortcut:

1. Adding `nomagic:ok` in bulk to make the gate green. `apps/api/src` already has 27 of them in 14
   files, all with a written reason (`# nomagic:ok batas teknis ...`). This task adds none; the
   diff must show zero new escape hatches, and any new one needs a reason in the diff review.
2. Widening `allowedInts` with whatever the run happens to flag. Any addition to the technical
   allowlist is named in the report with the constant it covers.

Out of scope: fixing the findings the baseline will capture. That is the shrink work P0a hands to
later phases, and `docs/BACKLOG.md` T-179 reads the count.

## Rule shape for handlers (decided 2026-11-16, before the baseline was captured)

`apps/api/src` is scanned by the **same three literal rules** as `modules/*/domain|application`
(business string, decimal, non-technical int), with one addition and one fence:

1. **Scoped technical allowlist.** A second list, `handlerAllowedInts` in
   `tools/lint-nomagic/lib.nim`, applies **only** under `apps/api/src/`. It is a closed set, not
   "whatever is red today":
   - HTTP status codes used by this API (RFC 9110 registry): 200, 201, 204, 300, 400, 401, 403,
     404, 405, 409, 415, 426, 429, 500, 501, 503.
   - Port bounds: 8080 (dev port), 65535 (maximum port).
2. **The modules list is untouched.** `allowedInts` still governs
   `modules/*/domain|application` exactly as before, so adding `200` for handlers does **not**
   make `200` legal as a business ceiling in a domain file. A unit case pins this
   (`allowlist handler tidak bocor ke domain/application`).
3. **Everything else that is red goes to the baseline as debt**, including literals that look
   technical (timeouts, buffer sizes, exit codes, calendar arithmetic). They are not excused with
   `# nomagic:ok`: the diff adds **zero** new escape hatches, and `apps/api/src` still carries the
   same 27 that were there before this task.

Rationale: HTTP status codes are 869 of the 981 findings (176×409, 163×500, 161×200, 133×403,
104×404, 63×400, 52×201, 7×204, plus single digits). Baselining them would have produced a ~900-line
file that goes stale every time a handler changes a status, which is how a gate gets switched off.
They are also not business values by construction. The remaining 112 findings collapse to 56 distinct
`rule|path|value` keys, which is a reviewable debt list.

## Baseline

`tools/lint-nomagic/baseline.txt` — 56 entries, key `rule|path|value`, no line numbers (same shape
and semantics as `tools/archcheck/baseline.txt`): a listed finding is accepted, an unlisted one
fails, and a listed one that no longer occurs fails with "baseline stale, shrink it".

| Rule | Entries |
|---|---|
| `int` | 47 |
| `str` | 5 |
| `dec` | 4 |

Two of the 56 are genuine business values and are debt, not technical constants:
`str|apps/api/src/handlers_lending_reports.nim|110` and `|111` — the GL account codes
(`glLoanReceivable`, `glLoanAllowance`) hardcoded in the reports handler. They belong in parameters
in a later phase; this task only makes them visible and counted.

## Acceptance

1. Seed one business value in a handler (for example `const minAge = 17` in
   `apps/api/src/handlers_party.nim`) → `./task nomagic` exit 1, names file, line and value. On the
   parent commit the same seed passes, which is the bug.
2. Seed one technical constant that must stay allowed (for example `const statusOk = 200`) → exit 0,
   and the allowlist entry that makes it pass is named in the report.
3. Remove one line from `baseline.txt` while its finding still exists → exit 1, "new finding".
4. Fix one real baselined finding without editing the baseline → exit 1, "baseline stale"; removing
   that line then makes it green. This is the shrink-only proof.
5. `./task nomagic` on the clean tree exits 0 and prints the baseline count; `./task check-fast`
   stays 8/8.
6. `tools/lint-nomagic/tests/tnomagic.nim` covers the new category and all three baseline outcomes;
   `./task test tnomagic` green.

## Notes

Written at DoR time, before implementation, so the implementer does not have to guess: the baseline
exists to make the gate a ratchet, not to make today's tree green. A finding in a handler that is
really a business value belongs in the baseline as debt and is reported as such; it is not excused
with an escape hatch.

## Post-landing fix (release gate, 16 Nov 2026)

The first release run after landing failed the gate on its own version bump:
`apps/api/src/version_gen.nim` is generated by `tools/gen-version.sh` but does not live under a
`generated/` path, so the stamped `VERSION` string was scanned as a business value. Every release
would have produced one new finding plus one stale baseline entry. `scanSource` now skips a file
whose first line carries the generator header (`JANGAN EDIT`), the baseline dropped from 56 to 55
entries, and two tests cover the skip (generated file ignored, ordinary file still scanned).
