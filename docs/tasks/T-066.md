# T-066 — Degradasi senyap pemantau deadline

Status: **selesai** 24 Okt 2026. Asal: temuan MINOR reviewer T-065. Rujukan: spec §12.1, T-065.

## Scope

`armDeadline` (`shared/platform-lib/db/deadline.nim`) mengembalikan token 0 bila batas tidak bisa
dipasang — disengaja, karena pemantau hanyalah lapisan tambahan dan kegagalannya tidak boleh
membuat kueri sehat ikut gagal. Masalahnya: kegagalan itu **tidak terlihat**. Bila tabel slot penuh
atau thread pemantau gagal dibuat, seluruh proses berjalan tanpa batas tanpa satu pun jejak.

Perbaikan (tanpa dependensi baru, tanpa metrik Prometheus — itu Fase 9):

1. Penghitung `deadlineUnarmedTotal()` (di bawah lock) untuk setiap kegagalan **internal**
   (slot penuh / thread gagal), bukan untuk `fd` atau batas yang memang tidak sah.
2. Satu log JSON terstruktur pada kejadian pertama: `cause` = `slot_table_full` atau
   `watchdog_thread`, field `deadline_unarmed_total`. Sengaja **sekali saja** — bila tabel penuh,
   setiap `withConn` akan menulis baris dan menenggelamkan log lain. Penghitung tetap naik.
3. Perbaikan perilaku yang ditemukan saat menulis test: bila `createThread` gagal, kode lama tetap
   memakai slot dan mengembalikan token != 0 — padahal tidak ada pemantau, jadi batasnya ilusi.
   Sekarang kondisi itu melepas token 0 dan tercatat sebagai degradasi.
4. Hook `setDeadlineLogSink` supaya test bisa menangkap baris log tanpa menulis ke stderr.

## Bukti

- `./task test tdeadline` — 4 `[OK]`, termasuk kasus baru: tabel penuh → `token == 0`, penghitung
  +1, tepat **satu** baris log berisi `"cause":"slot_table_full"` dan
  `"deadline_unarmed_total"`; panggilan berikutnya menambah penghitung tanpa menulis log lagi.
- `./task test tlog` — hijau (format log tidak berubah).
- `./task fmt` + `./task check` — hijau.

## Catatan

- `deadlineSink` hanya diisi oleh test; di produksi log memakai sink stderr bawaan `newLogger`,
  sejalan dengan log aplikasi lain.
- `deadlineUnarmedTotal()` belum diekspos lewat `/readyz` atau `/healthz`; menambah probe runtime
  adalah pekerjaan observabilitas Fase 9 (`docs/ACCEPTED-LIMITS.md`). Yang ditutup di sini adalah
  "tidak ada jejak sama sekali", bukan "ada metrik kontinu".
