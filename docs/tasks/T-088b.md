## Keputusan penting

1. **`deposit.transaction` di `0004`, bukan `0003`.** Urutan migrasi `(seq, modul, berkas)` menjalankan
   `deposit/*` **sebelum** `ledger/*` pada seq yang sama, jadi `deposit/0003` berjalan sebelum
   `ledger/0003`; FK ke `ledger.journal` wajib menunggu seq 4. Diverifikasi `./task dbtools validate`
   + `ittransaction` (migrasi dari skema kosong).
2. **Mutasi saldo = satu `UPDATE` bersyarat** pada `account_balance` (baris terkunci → dua koneksi
   bersamaan terserialisasi). 0 baris = 409 `insufficient_funds`; `CHECK balance >= 0` tetap backstop.
3. **Posting sinkron, bukan outbox.** `apps/api/src/deposit_posting.nim` memakai `selectRule` +
   `buildLines` + `journal_repo` (pola `handleReverseJournal`). Event outbox (`CashTransactionPosted`,
   `journal.posted`) **tanpa** header `accounting` agar konsumen `ledger` tidak memposting jurnal kedua.
4. **Kunci jurnal** `teller:<principalId>:<Idempotency-Key>` (≤200) = lapis kedua anti-jurnal-ganda;
   kunci terlalu panjang ditolak 400 (bukan dipotong). `minBalanceFor` di composition root membaca
   binding versi produk; binding ada tetapi bukan nominal sah = 500.
5. `narration` opsional ≤ 200 (batas teknis kolom).
