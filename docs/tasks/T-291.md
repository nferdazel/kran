## Scope

`/login`, `/app/print/*` and error pages stay outside the shell - this ticket re-proves it, because
it is the regression that is easiest to miss. Slip is A5 at 12/11, statement A4, and the heading
block repeats on page 2. Print output uses token colours through a `print` override; shadows and
scrims are off and no interactive control is visible.

Numbers follow the table rules from T-288/T-289: a report that prints a currency symbol in every
cell is a defect, not a style preference.

Deliberately not in scope: adding report types, PDF generation on the server, and any change to what
the statement contains.

## Acceptance

1. A test renders the print layout and asserts no element with the button or toolbar class is
   visible; asserting the reverse fails on a page that still shows controls.
2. The print block in `components.css` contains no `box-shadow` declaration and no raw hex; a test
   reads the block and fails if either appears. Removing the print block makes the test fail.
3. Both print routes render without the sidebar and topbar: the same assertion style as the shell
   ticket, run for `/app/print/slip/...` and `/app/print/statement/...`.
4. A statement fixture with a 3-digit and a 7-digit amount prints the currency once in the column
   header; the cell text matches the number pattern only.

Items 1-2 are automated. The A5/A4 page break, the repeated heading on page 2 and the absence of a
shadow are checked by printing to PDF at 100% and reading both pages; record the file path in
Evidence.

## Notes

Print is the one place where the dark theme must not leak: assert the paper is light in the PDF, not
only that the class names look right.

Implementation notes (T-291):

- Two page sizes from one stylesheet: the unnamed `@page` stays A4/12mm for the statement, and the
  slip article carries `.kran-print-doc--slip` with `page: slip`, selecting `@page slip { size: A5;
  margin: 12mm 11mm }`. Measured from the PDF, not from the CSS text.
- The statement heading moved into `<thead>` as a `td colspan="6"` row (`.kran-print-head`) so the
  whole header group repeats; `aria-labelledby="statement-heading"` still points at the same h1.
  Base `.kran-table td` sets `block-size` and zero block padding, but a table cell cannot clip its
  content, so the row grows on screen without any screen-only rule. No CSS beyond the print block
  was needed, which kept the change inside the file bounds.
- The print block still declares no colour at all: colour comes from the tokens, and
  `packages/ui/tokens/tokens.css` already forces light values for `@media print` (including dark).
