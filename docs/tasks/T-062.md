# T-062 — `startApi()` di luar `try/finally` membocorkan proses `kran-api`

Status: **DONE** (19 Okt 2026). Sumber: `docs/tasks/T-044.md` (temuan sampingan H1).

## Masalah

`apps/web/tests/e2e/shutdown.spec.ts` memanggil `startApi()` **sebelum** `try`. Kalau helper itu
melempar (API tidak siap dalam 20 s, mis. DB/tunnel mati), `child.kill()` di `finally` tidak pernah
terpasang — proses `kran-api` tetap hidup di port bebas, dan run berikutnya mewarisi proses yatim
(gejala "menggantung" pada T-044 lebih sulit dibaca).

## Rencana

1. Helper `startApi` membersihkan dirinya sendiri: bila readiness gagal/timeout, `SIGKILL` anak
   sebelum melempar galat. Galat membawa `pid` supaya bisa diperiksa.
2. Test baru: `startApi({ healthPath, readyTimeoutMs })` diarahkan ke rute 404 dengan batas 1,5 s →
   harus melempar "API tidak siap" **dan** PID-nya sudah tidak hidup.
3. Signature tetap kompatibel (parameter opsi, default sama).

## Kriteria selesai

- Subset e2e `shutdown.spec.ts` hijau (3 test, termasuk yang baru).
- Tidak ada proses `kran-api` sisa setelah test gagal-disengaja.
