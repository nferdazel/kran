# T-006 — Auth + RBAC + audit context + branch scoping

Spec: §13 (AuthN/AuthZ, cookie sesi, audit context), §18.2 (identitas & akses, otorisasi,
audit trail, logging tanpa PII), §9.2 (daftar tabel), §10 (kebijakan sebagai parameter).

## Scope

1. **Skema** `migrations/0006_platform_auth.sql`: `app_user`, `role`, `permission`,
   `role_permission`, `user_role` (dengan `branch_id`), `role_conflict` (matriks SoD), `session`.
2. **Domain murni** `domain/authz.nim`: validasi kode izin `modul.resource.action`, branch
   scoping, keputusan `authorize` (termasuk fail-closed saat SoD dilanggar), kebijakan sesi
   (idle/absolut, atribut cookie), kebijakan password (panjang).
3. **Domain murni** `domain/scope.nim`: `ScopeRef` + konvensi lookup parameter (dipakai kalender
   & auth; satu definisi).
4. **Hash password** `infrastructure/password_hasher.nim`: PBKDF2-HMAC-SHA256 (nimcrypto),
   bentuk tersimpan `algo$iterasi$salt$digest`, perbandingan waktu-tetap; hash token sesi
   (SHA-256) terpisah dari hash password.
5. **Repo** `infrastructure/auth_repo.nim`: user (status, lockout), role/permission/SoD,
   grant/revoke role (+ branch), sesi (buat/aktif/touch/cabut/cabut semua/purge).
6. **Alur** `infrastructure/auth_service.nim`: `authenticate` (lockout, verifikasi, sesi, audit),
   `sessionFor`, `touch`, `logout`, `logoutAll`, `authorizeUser`, `changePassword`,
   `settingsOf` (kebijakan dari parameter).
7. **Parameter baru**: `password_pbkdf2_iterations`, `max_failed_logins`, `lockout_minutes`,
   `session_absolute_minutes` (+ `session_idle_minutes` & `password_min_length` sudah ada).
8. **Test**: `tauthz` (19), `tpassword` (12), `itauth` (13).

## Keputusan penting

- **PBKDF2-HMAC-SHA256 dari `nimcrypto`** (pinned `>= 0.7.3`, sudah terpasang). Alternatif yang
  ditolak: menulis SHA-256/PBKDF2 sendiri (anti-pola kriptografi), dependensi native
  (libsodium/argon2) yang harus ada di dev **dan** server. Vektor uji dihitung **independen**
  dengan Python `hashlib.pbkdf2_hmac`, bukan dari pustaka yang sama. Dicatat D-013 +
  `HUMAN-REVIEW-REQUIRED` (area kriptografi).
- **Token sesi ≠ password**: token 256-bit acak dari `std/sysrand`, di DB hanya SHA-256-nya
  (hash cepat cukup untuk entropi tinggi).
- **Anti-enumerasi akun**: user tak dikenal dan password salah sama-sama
  `INVALID_CREDENTIALS`; bedanya hanya di audit. Nama user tak dikenal tidak ditulis mentah di
  audit (dipakai digest 16 hex, spec §18.2 logging tanpa PII).
- **SoD dua lapis**: penugasan role yang melahirkan konflik **ditolak** (`grantRole`), dan bila
  konflik tetap ada di data (jalur istimewa/data lama) `authorize` menolak **semua** aksi
  (fail-closed).
- **Branch scoping**: `user_role.branch_id` NULL = semua cabang; aksi level institusi
  (`targetBranch == ""`) hanya boleh oleh grant tanpa batas cabang.
- **Waktu eksplisit**: repo menerima `nowIso`/`expiresAtIso` dan membaca timestamp sebagai UTC
  bentuk tetap `...Z`, sehingga perbandingan string = perbandingan waktu dan test bisa
  time-travel (`FakeClock`).
- **Matriks SoD sengaja tidak diisi** di repo: pasangan yang dilarang adalah kebijakan
  institusi/compliance, bukan tebakan pengembang (OPEN_ITEMS O-016).
- **Nama tabel `app_user`** (bukan `user`): `USER` kata kunci SQL — lihat D-014.

| Kriteria | Bukti |

## Batasan yang diketahui (jujur)

1. **MFA (TOTP/WebAuthn) belum ada.** Spec §13/§18.2 memintanya; di luar kriteria T-006 dan
   butuh keputusan (pustaka/implementasi). Diusulkan sebagai T-017 (OPEN_ITEMS O-015).
2. **Belum ada HTTP layer**: atribut cookie sudah ditentukan & diuji sebagai string, tetapi
   penyetelan cookie nyata menunggu ADR-002 (E-001).
3. **Alur ini di `infrastructure`, bukan `application`.** Archcheck melarang `application`
   mengimpor `platform-lib/db`; sampai port/use case lahir (pola T-016), alur DB nyaman di
   `infrastructure`. Saat port lahir, isi `auth_service.nim` pindah ke `application/`.
4. **Belum ada endpoint admin** untuk membuat user/menugaskan role (dipakai lewat repo/CLI nanti);
   belum ada UI (T-010).
5. **Deteksi sesi ganda** (spec §18.2) belum: `activeSessionCount` tersedia, kebijakan
   (tolak/peringatkan) belum ditetapkan pemilik.
6. **RLS branch scoping** (spec §18.3, opsional) belum; penyaringan cabang masih di aplikasi.
7. **Rate limiting** (§13) belum; lockout per akun sudah.
8. **PII masking** untuk `full_name` di log belum relevan (belum ada log HTTP); `platform-lib/log`
   sudah punya masking untuk dipakai nanti.
