# T-151 — Kebijakan kata sandi terbaca sebelum ditolak

Status: **DONE (31 Okt 2026)**. Rujukan: O-051, D-138.

## Masalah

Kebijakan kata sandi hidup di parameter institusi dan hanya muncul sebagai penolakan
`400 password_policy`. Layar ganti sandi karenanya hanya bisa menyebut aturan yang stabil (tidak sama
dengan username, tanpa spasi) — pengguna baru tahu panjang minimum dan aturan riwayat setelah gagal.

## Perubahan

| Berkas | Perubahan |

| `apps/api/src/handlers_auth.nim` | `handlePasswordPolicy` — `GET /api/v1/auth/password-policy`, butuh sesi sah |
| `apps/api/src/routes.nim` | rute `getPasswordPolicy` |
| `packages/contracts/openapi/kran-api.yaml` | path + skema `PasswordPolicy` (`minLength`, `minClasses`, `historyCount`) |

| `apps/web/src/routes/app/password/+page.svelte` | petunjuk memakai kebijakan nyata; gagal memuat = petunjuk statis |
| i18n id+en | `password_hint_policy` |

## Keputusan

Hanya angka yang membentuk aturan yang dibagikan. `pbkdf2Iterations`, `maxFailedLogins`,
`lockoutMinutes`, dan umur sesi **tidak** ikut: itu informasi untuk penyerang, bukan untuk pengguna
yang sedang mengganti sandi. Kebijakan dibaca ulang saat layar dibuka, bukan ditulis di UI, supaya
perubahan parameter tidak menuntut rilis ulang.
