# T-095 — Pintasan keyboard teller terkonfigurasi

Status: DONE (23 Okt 2026)
Sumber: `docs/tasks/T-088.md` §7, spec §14.3/§17

## 1. Masalah

Milestone Fase 2 menuntut "alur teller keyboard-only lulus a11y". Setelah T-108, alur bisa
diselesaikan dengan Tab/Enter, tetapi pintasan papan tunai masih berupa TODO dan tidak boleh
dikarang sebagai konstanta UI.

## 2. Keputusan

- Tiga parameter baru di `modules/platform/seeds/params.yaml`:
  `platform.ui.shortcut.deposit` (`F4`), `.withdrawal` (`F5`), `.transfer` (`F9`).
  Scope `GLOBAL, INSTITUTION`, sensitivitas `NORMAL`, perubahan lewat alur maker-checker parameter.
- UI membaca `GET /api/v1/params` sekali saat mount, memetakan **hanya** key di atas. Tidak ada
  fallback hardcode: parameter tidak terbaca (mis. role teller tanpa `platform.param.read`) berarti
  pintasan mati; tombol biasa tetap bekerja.
- Handler menolak saat ada modifier (Ctrl/Alt/Meta), saat bukan fase `edit`, atau saat rekening
  belum dimuat. F2 (cari anggota) tidak diikat karena pencarian anggota belum ada.
- Perilaku murni (`shortcutModeForKey`) diuji vitest; alur nyata diuji e2e.

## 3. Bukti

- `shared/kernel/generated/paramkeys.nim`, `packages/contracts/src/generated/params.ts`,
  `packs/base/generated/{param_definitions,param_values}.sql` + provenance diregenerasi
  `./task paramgen-gen`; `./task check-fast` hijau (termasuk `paramgen --check`).
- Unit web 35 test; `svelte-check` 0 warning.
- `./task e2e` 26 test hijau, termasuk: setelah rekening dimuat, `F5` memilih Tarik, `F9` memilih PB,
  `F4` kembali ke Setor, lalu seluruh alur buka sesi → setor → tutup diselesaikan keyboard-only.

## 4. Batas

- Pintasan hanya mengubah mode; fokus pindah ke nominal, operator tetap meninjau sebelum simpan.
- Command palette Ctrl+K (spec §14.3) belum dibuat; bukan kriteria milestone dan belum ada
  kebutuhan operasional. Dicatat sebagai T-110 bila pemilik memintanya.
