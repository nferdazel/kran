# T-105 — Cari rekening berdasarkan nomor rekening

Status: READY (rencana; belum diimplementasi)
Sumber: `docs/tasks/T-088d.md` §Q4/blocker, `docs/BACKLOG.md` T-105
Prasyarat: T-088a (modul `deposit`, `GET /deposit/accounts`), D-123 (format nomor provisoris)

## 1. Masalah

UI teller saat ini hanya bisa memuat rekening lewat `GET /api/v1/deposit/accounts/{accountId}`,
padahal teller memegang **nomor rekening** dari nasabah, bukan UUID. Tanpa lookup, layar teller
memaksa operator menyalin UUID (tidak mungkin di operasi nyata). T-105 menutup celah itu.

## 2. Keputusan bentuk (usul, konservatif)

**Perluas endpoint daftar yang sudah ada**, bukan menambah path baru:

```
GET /api/v1/deposit/accounts?accountNo=<nomor>
```

- Tepat satu dari `partyId` atau `accountNo` wajib diisi. Keduanya kosong → 400
  `partyId atau accountNo wajib diisi`; keduanya terisi → 400 (tidak menebak prioritas).
- Respons tetap `{"items": [...]}` dengan `accountJson` yang sama (sudah memuat `accountId`,
  `accountNo`, `branchId`, saldo). UI memakai `items[0]`.
- Nomor tidak ditemukan → `items: []` (200), **bukan** 404: endpoint daftar tidak membocorkan
  keberadaan rekening lintas cabang. Rekening di cabang yang izinnya tidak dipegang juga
  tersaring per baris (pola D-062), sehingga hasilnya sama dengan "tidak ditemukan".
- Tanpa rate-limit khusus (belum ada mekanismenya di API); nomor provisoris 10 digit (D-123)
  membuat enumerasi murah — catat sebagai O-item bila pilot memakai data nyata.

Alasan tidak memakai path `/accounts/by-number/{accountNo}`: route daftar sudah ada, kontrak
dan gerbang cabang per baris bisa dipakai ulang, dan tidak menambah operasi baru di OpenAPI
(hanya parameter opsional + aturan saling-eksklusif).

## 4. Test yang wajib

1. `accountNo` milik cabang sendiri → 200, `items.len == 1`, `accountId` benar.
2. `accountNo` milik cabang lain (izin hanya cabang sendiri) → 200 `items: []` (bukan 403/404).
3. `accountNo` tidak ada → 200 `items: []`.
4. `partyId` + `accountNo` sekaligus → 400; keduanya kosong → 400 (test lama `partyId` tetap).
5. Tanpa izin `deposit.account.read` → 401/403 (sudah ada di endpoint, cukup regresi).
6. `tcontract` + `checkJson` untuk respons baru (skema tidak berubah → pastikan tetap lolos).
7. UI: unit test validasi nomor (hanya 10 digit) + pemetaan `items: []` → pesan "rekening tidak
   ditemukan"; e2e teller memakai nomor dari seed/fixture.

## 6. Risiko / batas

- **Nomor masih provisoris** (D-123, O-095): pencarian berdasarkan 10 digit tanpa check digit.
  Bila pemilik memutuskan format lain (prefix cabang/check digit), validasi pola di handler dan
  kontrak ikut berubah; jangan mengarang format sebelum keputusan.
- Tanpa rate-limit: enumerasi 10 digit dapat dilakukan; untuk pilot internal dapat diterima,
  untuk data nyata perlu pembatasan (catat, jangan diam-diam dianggap aman).
- Nomor rekening bukan rahasia, tetapi hasil lookup memuat `partyId` + saldo; izin
  `deposit.account.read` dan gerbang cabang tetap wajib (sudah).
