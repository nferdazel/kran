# T-054 — O-006: fondasi enkripsi field-level (KEK→DEK + blind index)

Status: **IN_PROGRESS → selesai (menunggu review manusia)** — 16 Okt 2026.
Prioritas: P1 (fondasi keamanan; Fase 1 `party` akan mendaratkan NIK/NPWP/no. HP/alamat).
Keputusan terkait: ADR-017, D-048; spec §18.2. Menutup O-006.

## Kenapa

Register O-006 berbunyi "KEK belum ada tempat aman". Itu **kurang**: kenyataannya **enkripsi
field belum ada sama sekali** — tidak ada `.nim` yang menyebut `KRAN_KEK*`/`encryptField`,
`KRAN_KEK_FILE` hanya komentar di `ops/env/kran-prod.env.example`, dan `pgp_sym_encrypt` nol di
migrasi. Pemilik memutuskan mekanisme ini **bagian fondasi** dan dikerjakan sekarang, bukan
menunggu data anggota nyata (menambah enkripsi setelah baris ada = backfill + seremoni kunci).

## Batas & keputusan bentuk

- Bentuk dikunci spec §18.2: envelope (KEK dari server/KMS, **DEK per tabel/record**), **blind
  index** untuk pencarian.
- AES-256-GCM dari `nimcrypto` (`rijndael` + `bcmode`) — **tanpa dependensi baru**.
- Ditaruh di `shared/platform-lib/` (bukan `modules/platform`) karena Fase 1 `party`/`lending` juga
  butuh dan `shared/*` boleh diimpor modul mana pun; `shared/kernel` dilarang (nimcrypto pihak
  ketiga).
- **Lingkup = mekanisme**, bukan menyulap kolom: belum ada kolom PII untuk dienkripsi; kolom nyata
  menyusul di Fase 1.

## Kriteria selesai (dari permintaan)

- [x] Hierarki kunci: KEK berkas terpisah mode 600, satu/lebih kunci berversi; DEK **diturunkan**
  per tabel (tanpa materi kunci di DB).
- [x] KDF paling sederhana yang benar: `HMAC-SHA256(KEK, info)` (bukan HKDF penuh) — dengan vektor
  independen Node.
- [x] Ciphertext self-describing `kran:enc:v1:<kid>:<nonce>:<ct||tag>`, AAD = nama tabel, nonce
  96-bit CSPRNG; gagal dekripsi = `DecryptError` eksplisit (bukan kosong/plaintext).
- [x] Blind index HMAC-SHA256 dengan kunci turunan terpisah + `normalizeDigits` untuk field angka.
- [x] Aktivasi: `KRAN_KEK_FILE` kosong → start seperti sekarang (enkripsi menolak eksplisit); diset
  → fail-fast saat startup. Tanpa fallback diam-diam (O-056/D-046 butir 6).
- [x] Uji: roundtrip (kosong/multibyte/100 iterasi), tamper 1 bit, AAD lintas tabel, kid tak
  dikenal/berkas rusak/hilang, blind index, tanpa plaintext/kunci di galat, vektor independen.
- [x] Ops: env contoh + runbook; berkas KEK tidak ikut backup DB (O-006).
- [x] `HUMAN-REVIEW-REQUIRED` di header berkas kripto.

## Batas yang jujur

- Ini **fondasi**; belum ada kolom PII yang dienkripsi. Data nyata baru boleh masuk setelah review
  manusia (AGENTS.md §8) dan setelah kolom PII mendarat di Fase 1.
- Rotasi tidak independen per tabel (DEK terikat KEK); rotasi kunci blind index butuh reindex.
- `KRAN_KEK_FILE` **sudah** divalidasi saat startup biner `api` (fail-fast bila diset & rusak) dan
  keyring disimpan di `AppContext`, tetapi **belum ada konsumen** (belum ada kolom PII) — belum ada
  jalur enkripsi nyata yang memakainya.
- Normalisasi Unicode nama/alamat belum ditetapkan (open item, tidak dikarang).
- Registri ADR spec §25 belum diubah (suntingan spec diserahkan ke manusia); teks barisnya ada di
  laporan T-054.
