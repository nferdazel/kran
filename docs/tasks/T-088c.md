## Scope

Masuk:
1. `deposit/0007_deposit_transfer.sql`: tabel `deposit.transfer` (`source_account_id` +
   `destination_account_id` FK `deposit.account`, `amount numeric(24,4) > 0`, `business_date`,
   `narration`, `journal_id` UNIQUE FK `ledger.journal`, `created_*`, CHECK akun berbeda). Tanpa
   `currency`. Plus trigger immutability (`ledger.reject_mutation`).
2. `deposit/0008_deposit_transfer_grants.sql`: grant runtime untuk tabel baru (`0006` hanya mencakup
   tabel yang ada saat itu; tabel `0007` dibuat belakangan → tanpa ini `kran_runtime` gagal di
   produksi).
3. `ledger/0013_ledger_posting_rules_transfer.sql`: rule `DepositTransferred` = D 201 / K 201
   (idempoten).
4. `POST /api/v1/teller/transfers` → 201 `Transfer`; izin `teller.transaction.post` di **kedua**
   cabang; `Idempotency-Key` wajib; kunci jurnal `teller:<principalId>:<key>`.
5. Satu `withDbTx` + `withIdempotency`: kunci dua baris saldo urut `account_id` naik, kurangi sumber
   (`WHERE balance - amount >= min_balance` versi produk sumber), tambah tujuan; 0 baris → 409
   `insufficient_funds`; non-ACTIVE → 409 `account_not_active`; periode tutup → 409 `period_closed`
   (rollback penuh). Audit `deposit.transfer.post`; outbox `TransferPosted` + `journal.posted`
   **tanpa** header `accounting`.
6. Nominal `Money`/string desimal, tanpa float. Tanpa i18n (belum ada UI).

Tidak masuk: UI/088d, sesi/vault, akrual bunga, GL per pemilik (T-101/Fase 3), batas nominal (T-093).

## Keputusan penting

1. **Tabel baru, bukan `ALTER deposit.transaction`.** CHECK `tx_type` di `0004` hanya CASH_*;
   menambah `TRANSFER` = DROP CONSTRAINT (destruktif) → ditolak expand-only. Tabel `deposit.transfer`
   memisahkan bentuk (dua rekening) dari transaksi tunai (satu rekening + arah).
2. **Anti-deadlock:** baris saldo kedua rekening dikunci `SELECT ... FOR UPDATE` urut `account_id`
   naik (`lockBalancesAscending`) **sebelum** mutasi. Dua PB berlawanan arah selalu mengunci baris
   terkecil dulu → tak ada siklus tunggu. Syarat saldo dievaluasi setelah kedua baris terkunci, jadi
   0 baris tidak meninggalkan kredit nyangkut di tujuan.
3. **Posting sinkron** (`postJournalSync`, pola 088b) dengan rule data `DepositTransferred`. Batas:
   kedua sisi GL akun `201` sama → jurnal net-nol di GL; perpindahan per rekening di
   `deposit.transfer`. Dicatat `MODULE.md` + `docs/ACCEPTED-LIMITS.md`.
4. Kunci jurnal `teller:<principalId>:<Idempotency-Key>` (≤200) = lapis kedua anti-jurnal-ganda.
