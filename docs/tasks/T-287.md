## Scope

`Button` keeps its current props and gains `quiet` as a fourth visible variant next to primary,
secondary and destructive, plus a `size` prop (`sm` 32, `md` 40). The existing `row` variant stays
and maps to 32 so the tables do not change; `size` wins when both are given. `loading` keeps the
label, keeps `aria-busy="true"` and still blocks the second click.

Interaction rules: quiet and secondary hover to `--surface-2`; primary hover only raises brightness
to 1.06 with no colour shift and no shadow change; active is one step darker than hover, not a new
colour; disabled on primary does not switch the cursor to `not-allowed`.

Deliberately not in scope: any screen's button copy or placement, icon set changes, a tooltip
component, and button variants for print.

## Acceptance

On the parent commit the new cases fail because `quiet` and `size` are not in `Props`:

1. `variant="quiet"` renders the class `kran-button--quiet` and no other variant modifier.
2. `size="sm"` renders the 32 class, `size="md"` the 40 class, and no `size` renders 40.
3. `variant="row"` without `size` still renders the 32 class (existing call sites keep their look).
4. `loading` renders `aria-busy="true"` and `disabled`; the label text stays in the DOM.
5. All existing call sites compile unchanged: `pnpm exec svelte-check` reports 0 errors.

Hover and active are CSS-only rules; they are verified by reading the built stylesheet for the two
properties (no `--color-*` override in the primary hover/active rule) and by a manual pass in both
themes recorded in Evidence.
