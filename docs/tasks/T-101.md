# T-101 — Rekonsiliasi cache saldo simpanan vs baris mutasi

Status: DONE (24 Okt 2026). Rujukan: D-096, D-124, `docs/ACCEPTED-LIMITS.md`.

## Scope

`deposit.account_balance` adalah **cache** untuk operasi saldo; sumber kebenaran mutasi rekening ada
di `deposit.transaction` (tunai) dan `deposit.transfer` (pemindahbukuan). Task ini menambah
pemeriksaan baca-saja yang membandingkan keduanya, supaya selisih cache terdeteksi sebelum
menyentuh laporan atau teller.

Masuk:
- Repo baru `modules/deposit/infrastructure/reconcile_repo.nim`: `accountBalanceMismatches`,
  `reconciledAccountCount`.
- `ctl reconcile-deposits [--branch=<uuid>]` (baca saja; exit 0 bersih, 1 ada selisih, 2 argumen
  salah).
- Suite integrasi `itreconcile.nim`: fixture tunai + PB + cache, selisih yang disengaja, filter
  cabang, cache hilang, dan kontrak kode keluar.

Tidak masuk:
- Penjadwalan otomatis (day-close Fase 3) dan koreksi otomatis. Selisih = temuan, bukan sesuatu
  yang ditulis ulang oleh alat ini.
- Rekonsiliasi GL per rekening: mustahil selama liabilitas simpanan dipool di akun `201` (D-124).

## Rumus yang dipakai

`expected = Σ tunai masuk − Σ tunai keluar + Σ PB masuk − Σ PB keluar`

Kenapa **bukan** `journal_line` per rekening: kedua kaki PB memakai akun `201` yang sama (net-nol),
jadi jurnal tidak bisa direkonstruksi per rekening. Ini juga sebabnya laporan GL per pemilik belum
ada (`ACCEPTED-LIMITS`, T-101/Fase 3).

## Bukti

- `./task test itreconcile` 3 OK: nol selisih pada data bersih (membuktikan kedua kaki PB dihitung,
  karena tanpa itu A=70 vs cache 50 dan B=0 vs cache 20), selisih `+5.0000` terdeteksi dengan
  `accountNo`/cabang/cache/expected/delta, filter cabang menyaring, cache yang hilang dilaporkan
  (`cached == ""`), `runCtl` exit 1/0/2 sesuai kontrak.
- `./task test` 1099 OK (suite berjalan di urutan normal bersama suite lain).
- `./task check-fast` dan `./task lint` hijau (217 berkas).

## Sisa (bukan bagian T-101)

- Jurnal simpanan yang dibalik lewat ledger **tidak** memutar baris `deposit.transaction`/`transfer`,
  sehingga cache tetap cocok dengan baris tetapi menyimpang dari GL. Perilaku itu belum diputuskan:
  catat sebagai task tersendiri (lihat `docs/BACKLOG.md` T-123).
- Penjadwalan harian menunggu framework daycloser (Fase 3).
