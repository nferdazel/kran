## Scope

Three controls own their own label, hint and error and wire `aria-describedby` themselves. The page
passes `label`, `hint`, `error`, `required`; it never passes an `id` and never assembles ids by hand.
`Field` stops existing at the end of this ticket, so there is one way to build a control, not two.

States rendered with a visible difference: default, hover, focus, disabled, invalid, readonly, filled.
Select stays a native `<select>`; checkbox keeps a real `<input>` (box 16, hit area may reach 40).

Deliberately not in scope: bare `<input>` outside `Field` (`login`, `params`, `teller`, `password`,
`statement`) stays native until its own screen ticket; no validation library; no new copy key; no
layout change to any screen beyond the control markup.

## Acceptance

`packages/ui/tests/components.test.ts` gains cases that fail on the parent commit because the three
components do not exist there:

1. Each control renders `label[for]` pointing at its own generated id; two controls with the same
   `label` never share an id.
2. `aria-describedby` lists hint then error, and only when that text is non-empty; an error alone
   gives one id, a hint alone gives one id.
3. `aria-invalid="true"` appears only when `error` is non-empty.
4. `Select` renders an actual `<select>` element (not a div with a role), and `Checkbox` renders
   `input[type=checkbox]`.
5. The three components contain no raw hex colour: `rg '#[0-9a-fA-F]{3,6}'` over the three files
   returns 0 matches.

Removing any one of the `aria-describedby` assignments makes case 2 fail; that is the proof the
assertion is load-bearing. After migration `rg "<Field" apps/web/src` returns 0 and
`pnpm exec svelte-check` is clean.
