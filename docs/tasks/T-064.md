# T-064 — daftar audit terurut leksikografis (bug ditemukan lewat e2e flow)

Status: **DONE** (19 Okt 2026). Ditemukan saat menjalankan e2e penuh setelah T-061/T-062.

## Gejala

`./task e2e` merah di `flow.spec.ts` (assertion "alasan pengajuan terlihat di Jejak audit"), padahal
barisnya ada di DB. `GET /api/v1/audit?limit=20` (login `dev.maker`, DB dev dengan 231 baris audit)
mengembalikan `99, 98, …, 90, 9, 89, …, 81` — bukan 20 baris terbaru.

## Akar masalah

`modules/platform/infrastructure/audit_repo.nim`: kolom keluaran `seq::text` diberi nama `seq`, dan
`ORDER BY seq DESC` diresolusi PostgreSQL ke **kolom keluaran (teks)**, bukan kolom tabel (bigint).
Akibatnya `'99' > '100'`: setelah ledger melewati 100 baris, baris terbaru tidak pernah masuk halaman
pertama. Database dev baru melewati 100 baris hari ini (banyak run test), jadi bug ini baru tampak.

## Perbaikan

`ORDER BY audit_log.seq DESC` (merujuk kolom tabel). Satu baris. Tidak ada perubahan kontrak API.

## Bukti

- Reproduksi API: `[99, 98, …, 90, 9, 89, …, 81]` sementara `SELECT max(seq) = 231`.
- Test regresi `itplatform` "urutan daftar = seq numerik, bukan teks (melewati 100)" menulis sampai
  >100 baris lalu menuntut baris teratas = `max(seq)`.
- **Uji mutasi**: dengan `ORDER BY seq DESC` test itu **FAILED**; setelah `audit_log.seq` → **OK**
  (`./task test itplatform` 25 `[OK]`, exit 0).
- `playwright test flow.spec.ts` → **6 passed** setelah perbaikan.
