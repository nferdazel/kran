## Scope

Two new categories, each with its own rule set, and a baseline that can only shrink.

| Category | Paths | Rule |
|---|---|---|
| `catHandler` | `apps/api/src/**/*.nim` (excluding `apps/api/src/generated/`) | may import `modules/<m>/api`, `modules/<m>/application/*`, `shared/*`, `platform-lib/*`, other files under `apps/api/src`, stdlib. **Forbidden**: `modules/<m>/infrastructure/*` and `modules/<m>/domain/*` — a handler reaches the database through the module's application/api surface. |
| `catTest` | any path containing `/tests/` | may import its own module freely, `shared/*`, `platform-lib/*`, stdlib. **Forbidden**: `modules/<other>/infrastructure/*` and `modules/<other>/domain/*`; a module's tests must not bind themselves to another module's internals, or the extraction in P2 cannot move without breaking them. |

`tools/**` and `/generated/` stay `catSkip`.

Baseline mechanics (`tools/archcheck/baseline.txt`, one `rule|path|import` line per accepted
violation, sorted):

- a violation not listed → exit 1, new violation.
- a violation listed but no longer occurring → exit 1, "baseline stale, shrink it".
- no mechanism to append automatically. Adding a line is a hand edit and must be justified in the
  commit message; the lead reviews it.
- `--update-baseline` writes the file for the initial capture only, and the commit that introduces
  it states the count per rule.

Rule set is deliberately one forbidden-import predicate per category, not a full dependency matrix.
If the first capture shows a rule that is wrong for a legitimate reason (not merely "lots of
violations"), stop and report it before changing the rule; loosening a rule after the fact is the
failure mode this task exists to prevent.

Out of scope: `lint-nomagic` coverage of `apps/api/src` (T-174), handler business-rule extraction
(P2b), and any restructuring of existing violations.
