# T-173 — Aksi tulis pinjaman di UI (pencairan, pembayaran, restrukturisasi, hapus buku)

Status: **IN PROGRESS — kode selesai, gate hijau, menunggu review independen** (2 Nov 2026). Prasyarat T-170 (`DONE`, baca-saja) dan endpoint tulis
T-163…T-168 (`DONE`) sudah ada; task ini **hanya** menambah jalur UI, bukan aturan bisnis baru.
Prioritas: P1 (operator pilot tidak boleh memindahkan uang lewat API mentah).

## Scope

Empat aksi di layar detail pinjaman (`apps/web/src/routes/app/loans/[loanId]`), masing-masing
dengan pratinjau sebelum dikirim:

| Aksi | Endpoint | Body | Izin |
| --- | --- | --- | --- |
| Pencairan | `POST /lending/loans/{loanId}/disburse` | `accountId` | `lending.loan.disburse` |
| Pembayaran angsuran | `POST /lending/loans/{loanId}/payments` | `accountId`, `amount` | `lending.loan.pay` |
| Restrukturisasi | `POST /lending/loans/{loanId}/restructure` | `tenorMonths`, `reason` | `lending.loan.restructure` |
| Hapus buku | `POST /lending/loans/{loanId}/write-off` | `reason` | `lending.loan.write_off` |

Bukan scope: pengajuan/persetujuan pinjaman (butuh layar party + produk; task terpisah bila perlu),
laporan, dan perubahan kontrak OpenAPI (tidak ada operasi baru).

## Keputusan desain

1. **Rekening sumber dipilih dari data, bukan diketik.** `GET /deposit/accounts?partyId=<partyId>`
   (`listDepositAccounts`) memakai `partyId` akad; hanya rekening `ACTIVE` di cabang akad yang
   ditawarkan. Server tetap memvalidasi (`account_party_mismatch`, `account_branch_mismatch`,
   `account_not_active`) — UI tidak boleh menjadi satu-satunya penjaga.
2. **Pratinjau = dialog konfirmasi berisi angka yang akan dikirim**, bukan perhitungan ulang di
   peramban: nominal, rekening sumber (nomor + saldo apa adanya), konsekuensi status (`ACTIVE`,
   jadwal versi baru, `WRITTEN_OFF`). Aritmetika uang tetap di server (AGENTS §1.3); tidak ada
   `Number` untuk uang.
3. **Idempotency-Key per percobaan kirim** (`crypto.randomUUID()`), dibuat saat dialog dibuka dan
   dipakai ulang bila pengguna menekan kirim dua kali; kunci baru hanya setelah sukses/gagal final.
4. **Alasan wajib** untuk restrukturisasi dan hapus buku (1–500 karakter) — sama dengan kontrak,
   tidak dilonggarkan di UI.
5. **Tombol tampil hanya bila izin dipegang** (`session.permissions`), tetapi 403 tetap dipetakan
   ke pesan yang jelas karena izin bisa berubah antar sesi.
6. Setelah sukses: muat ulang detail (`load()`) dan tampilkan `Alert` sukses berisi nomor jurnal
   (pencairan/pembayaran/hapus buku) atau jumlah angsuran + jatuh tempo (restrukturisasi).
