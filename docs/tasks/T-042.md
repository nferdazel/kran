# T-042 — Teardown in-process Mummy (O-025)

Status: READY. Prioritas: P3. Titip: server HTTP → HUMAN-REVIEW-REQUIRED bila menyentuh jalur shutdown.

## Kenapa
`server.close()` pada harness test (Mummy 0.4.8 + ORC) pernah SIGSEGV. Shutdown **produksi** sudah aman
lewat jalur lain (T-024/D-031: sinyal → hentikan pump → `quit(0)`), tetapi harness yang tidak aman berarti
`./task test` bisa mati mendadak tanpa pesan — dan restart bersih belum terbukti dari sisi API.

## Fakta yang sudah ada
- Probe 15 Okt: server minimal `close()` **tidak** crash; gejala bergantung konteks (server hidup
  bersama pool DB + thread pump, diteardown dari dalam proses test yang masih jalan).
- O-025 di `docs/OPEN_ITEMS.md` memuat rentetan probe itu.

## Rencana
1. Reproduksi sekecil mungkin (server + pool + pump, teardown dari dalam proses; catat urutan yang
   memicunya). Kalau tidak bisa direproduksi dalam waktu terbatas → tulis batas itu, jangan mengarang.
2. Bila ter-repro: cari urutan aman (mis. tutup pump & pool dulu, `quit` lewat kode keluar) atau upgrade
   Mummy bila ada perbaikan hulu; buktikan dengan test.
3. Perbarui O-025 + `ACCEPTED-LIMITS.md` dengan hasil apa pun (beres atau batas yang diterima).

## Kriteria selesai
- [ ] Ada repro minimal **atau** bukti bahwa gejala itu tidak lagi muncul pada urutan teardown yang dipakai.
- [ ] `./task test` hijau; tidak ada test yang dilonggarkan.
