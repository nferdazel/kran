# T-008 — OpenAPI skeleton + klien TS + contract test

Spec: §13 (REST/JSON, OpenAPI 3.1 = sumber kebenaran, klien TS di-generate, contract test),
§20 (contract test, `schemathesis`/validator JSON Schema), §21.4 #11 (`/healthz` `/readyz` dipakai
gate deploy), §19.1 (realtime lewat endpoint yang sama), ADR-002/D-019 (Mummy + WebSocket).

## Scope

Setelah keputusan pemilik (E-001 → opsi A, 2026-10-14) task ini dibuka kembali. Yang dikerjakan:

1. `packages/contracts/openapi/cbs-api.yaml` — kontrak OpenAPI 3.1 + `.spectral.yaml` (ruleset
   `spectral:oas` tanpa override).
2. `packages/api-client` — klien TS: tipe hasil generate (`src/generated/schema.d.ts`) + wrapper
   fetch tipis (`src/index.ts`, `openapi-fetch`, middleware `X-Request-Id`) + `tsconfig.json`.
3. `apps/api` — binari HTTP pertama: `main.nim` (role `--role=`), `server.nim` (Mummy + router),
   `routes.nim` (tabel rute), `health.nim` (`/healthz`, `/readyz`), `problem.nim` (RFC 9457),
   `readiness.nim` (probe DB), `db_bridge.nim` (gcm-safe boundary), `version.nim`.
4. `tools/openapi` — pembaca kontrak + validator **subset** JSON Schema 2020-12 + parity rute.
5. Test: `tools/openapi/tests/topenapi.nim` (20), `apps/api/tests/tcontract.nim` (4),
   `apps/api/tests/tapi.nim` (6, respons nyata vs kontrak), `apps/api/tests/itapi.nim` (2, DB nyata).
6. Gate baru `./task openapi` (lint + regen tanpa diff + typecheck klien) + step CI `web-e2e`.

Cakupan sengaja dibatasi: kontrak hanya memuat operasi yang **sudah** dilayani implementasi
(endpoint sistem). Endpoint auth/parameter/audit masuk bersama implementasinya di T-012; realtime
hub di T-009. Aturannya: menambah rute tanpa memperbarui kontrak (atau sebaliknya) = CI merah.

## Keputusan desain

- **Kontrak tumbuh bersama implementasi, bukan mendahului.** Alternatifnya (mendefinisikan seluruh
  kontrak Fase 0 sekarang lalu memberi *allowlist* "belum diimplementasikan") menciptakan gate yang
  bisa dilalui tanpa implementasi — kelas lubang yang justru dilarang AGENTS.md §5.
- **Subset JSON Schema, jujur soal batasnya.** Validator di `tools/openapi` memeriksa `type`,
  `required`, `properties`, `additionalProperties:false`, `enum`, `items`, `minimum` — kata kunci
  yang benar-benar dipakai kontrak. Bukan validator penuh: kalau kontrak mulai memakai kata kunci
  lain, validator harus ditambah **dan** diuji, bukan dilewati diam-diam. Menolak menjalankan
  `schemathesis` (disarankan spec §20) karena butuh Python + server berjalan di CI; dicatat O-026.
- **Handler Mummy di thread → `db_bridge`.** Mummy memanggil handler di worker thread (dan itu
  keuntungannya: handler boleh blocking, cocok `db_connector` sinkron spec §12.1), sementara
  handler wajib `{.gcsafe.}`. `withConn` platform-lib tidak gcsafe, jadi asumsi "pool aman dipakai
  antar-thread" ditegaskan satu kali di `db_bridge.nim` — bukan tersebar, dan pertama diperiksa bila
  O-011 (peminjaman paralel belum diuji) ternyata bermasalah.
- **`problem+json` untuk semua error yang kita kendalikan**: 404 rute tak dikenal dan 405 method
  salah pun memakai amplop RFC 9457 (bukan halaman HTML Mummy), supaya klien punya satu jalur
  penanganan error. Karena itu kontrak mendeklarasikan `405` pada kedua path.
- **Versi aplikasi** dari env `CBS_VERSION` (diisi deploy) dengan fallback konstanta; pengisian
  otomatis dari `git describe` belum ada (dicatat di `version.nim`).

## Bug nyata yang tertangkap verifikasi manual

Closure handler yang ditulis langsung di dalam loop `for spec in allRoutes()` membuat
**`/healthz` melayani handler `/readyz`** (health mengembalikan badan readiness). Ketahuan saat
smoke test `curl`, bukan oleh test (test saat itu belum ada). Perbaikan: `bindHandler(handler, app)`
sebagai proc terpisah + komentar di `server.nim`. Test `tapi` sekarang mengunci perilaku ini
(`/healthz` → bentuk `Health`, `/readyz` → bentuk `Readiness`).

## Batasan yang diketahui (jujur)

1. **`server.close()` tidak dipakai** — pada Mummy 0.4.8 + ORC, memanggilnya membuat proses mati
   (SIGSEGV di `destroy`, jejaknya di ORC cycle collector). Test sengaja tidak menutup server.
   Shutdown/restart yang benar harus diverifikasi sebelum deploy → O-025.
2. **Readiness memeriksa DB saja** (belum migrasi/versi schema, belum cek outbox lag). Migrasi
   sengaja tidak diperiksa karena schema platform sudah dibuktikan migrasinya di T-004.
3. **Belum ada `--role=migrate|ctl|worker`**; role selain `api` gagal cepat (exit 3) — O-013 tetap
   terbuka, dan itu berarti `ops/scripts/migrate.sh` & freeze gate **belum bisa dijalankan**.
4. **Belum ada auth/rate limit/CORS/body limit khusus** di server; endpoint yang ada hanya
   kesehatan dan tidak menerima data. Semuanya masuk T-012 bersama endpoint bisnis pertama.
5. **Belum ada `schemathesis`** (spec §20 menyebutnya sebagai contoh) → O-026.
6. **`X-Forwarded-*`/IP klien belum dibaca** walau `audit_log` nanti membutuhkannya; hanya
   `X-Request-Id` yang diteruskan ke `traceId`.
