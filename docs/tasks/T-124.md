# T-124 — Uang 2 desimal (penyimpanan, API, tampilan)

Status: in progress (24 Okt 2026). Rujukan: D-136 (menggantikan D-097), spec §9.1(2).

## Scope

Uang sebelumnya `numeric(24,4)` di DB dan `Money` berskala 10⁻⁴, sementara tampilan tunai sudah 2
desimal (D-097). Pemilik memutuskan satu presisi saja: **2 desimal di penyimpanan, API, dan UI**.

Masuk:
- `shared/kernel/money.nim`: `moneyScale = 2`, `moneyScaleFactor = 100`; `toDisplayString` dihapus
  (tugasnya hanya menjembatani 4 → 2).
- Migrasi expand-only `deposit/0038`, `ledger/0039`, `teller/0040`: 14 kolom uang → `numeric(24,2)`,
  plus `ledger.assert_journal_header_complete` (variabel lokal ikut 2 desimal) dan rebuild
  `balance_snapshot`.
- Kontrak OpenAPI: seluruh deskripsi "4 desimal" → "2 desimal"; klien TS digenerate ulang.
- Web/UI: `formatMoney`/`addMoney` default 2 desimal, `parseMoneyInput` menormalkan ke 2, seed
  parameter & fixture ikut 2 desimal.
- Test: literal 4 desimal → 2 desimal (698 penggantian mekanis di 117 berkas) dan kasus yang
  memang menguji sub-sen diperbaiki manual.

Tidak masuk:
- Akrual bunga (Fase 3). `rounding_scale`/`rounding_mode` (O-084) wajib diputuskan **sebelum**
  akrual ditulis: dengan skala 2, akrual harian membulat per sen.
- Perubahan `Rate` (tetap 1e-6): presisi persen bukan presisi uang.

## Migrasi: kenapa berhenti, bukan membulatkan

`USING round(x, 2)` pada tabel immutable (jurnal, transaksi teller) akan membuang nilai di bawah
0,01 tanpa cara mengoreksi. Ketiga migrasi memeriksa dulu dan **RAISE EXCEPTION** menyebut tabelnya
bila ada baris yang tidak sama dengan pembulatan 2 desimal.

Pra-cek produksi (24 Okt 2026, sebelum deploy):

| Tabel | Baris dengan nilai < 0,01 |
| --- | --- |
| `deposit.transaction` | 0 |
| `deposit.transfer` | 0 |
| `deposit.account_balance` | 0 |
| `ledger.journal_line` | 0 |
| `ledger.balance_snapshot` | 0 |
| `teller.vault` | 0 |
| `teller.cash_movement` | 0 |
| `teller.teller_session` | 0 |
| `teller.vault_topup_request` | 0 |
