## Scope

One drawer: 520 fixed width, full height, `--surface`, `--shadow-2`, width 100% below 640px. It
receives focus on open, traps Tab inside, closes on Escape and returns focus to the control that
opened it - the row button, never `body`. `aria-modal="true"` is set only if the trap works; if the
trap cannot be implemented in this ticket, the attribute is dropped and the component is not called
modal.

States: open, loading, error with retry, and the unsaved-change confirm on close. Closing from a
table row must not scroll the table away from that row.

First consumer is `/app/dayclose`, whose detail is an inline section today; converting it proves the
whole contract against a real trigger, which the mockup could not do.

Deliberately not in scope: a ledger detail feature (none exists yet), drawer content redesign,
nested drawers, any change to the dayclose actions themselves.

## Acceptance

New cases fail on the parent commit because `Drawer.svelte` does not exist:

1. Opening the drawer focuses the heading; the heading is the element named by `aria-labelledby`.
2. Pressing Escape closes it and `document.activeElement` is the exact trigger element that opened
   it (the test asserts identity, not `document.body` and not a selector match).
3. With `aria-modal="true"`, Tab from the last focusable element lands on the first, and Shift+Tab
   from the first lands on the last - the trap is asserted in both directions.
4. The rendered panel carries the 520 class, and the width-100% class is present for the narrow
   branch.
5. The dayclose row still opens the detail; `rg "dayclose_open_detail" packages apps` returns 0 after
   the migration and `./task check-fast` stays green (no orphan key).

Manual: at 1440 and 360, both themes, open from the last row of a long history table, close, and the
same row is still in view. Record it in Evidence.

### Notes on what the component tests can and cannot prove

`packages/ui` runs on `svelte/server` with `environment: "node"` and no jsdom (adding one needs an
ADR), so the suite cannot read `document.activeElement`. The acceptance cases are therefore split
in two halves that both fail on the parent commit: SSR markup (role, `aria-modal`,
`aria-labelledby` naming the focusable heading, the 520 and width-100% classes, the scrim's
`aria-hidden`, loading vs error states) and the pure focus contract exported from the component's
module script (`wrapTabTarget` in both directions, `restoreFocusTarget` identity and its
detached/disabled fallbacks). The wiring itself — Escape key, the window-level `onkeydown` with its
`open` guard, the dirty-confirm branch — is asserted against the component source, and the live
behaviour is proven in the browser by the manual pass above and the scrim-click case in
`dayclose.spec.ts`, not by the unit suite.
