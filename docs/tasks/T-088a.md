## Keputusan penting

### 1. Nomor migrasi akun = `0003`, bukan `0002` (deviasi dari rencana T-088)

Rencana T-088 §6 menaruh tabel akun di `deposit/0002`. Itu **salah urut**: urutan migrasi global
adalah `(seq, modul, berkas)` (`tools/dbtools/lib.nim:migrationsOf`), dan pada seq yang sama modul
yang abjadnya lebih dulu berjalan lebih dulu. Modul `deposit` < `product`, sehingga `deposit/0002`
berjalan **sebelum** `product/0002` yang membuat `product.product`/`product.product_version` —
padahal tabel akun mem-FK keduanya. Di DB kosong (jalur `db-tests` CI + `resetTestSchemas` harness)
migrasi akan gagal.

Bukti urutan (`./task dbtools validate`, sebelum perbaikan):

```
      2  deposit/0002_deposit_account        ← berjalan di sini
      2  product/0002_product_catalog        ← tabel FK baru dibuat di sini
```

Perbaikan minimal: tabel akun di `deposit/0003` (seq 3 > 2). `0002` sengaja dilewati. Aturan ini
dicatat sebagai **D-122**. Tabel yang mem-FK `ledger.journal` nanti (T-088b) tetap wajib seq ≥ 4.

### 2. Nomor rekening provisoris — **NEEDS-COMPLIANCE-REVIEW**

Tanpa parameter baru di task ini, nomor rekening = `formatAccountNo(seq)` = 10 digit zero-padded
tanpa check digit. Bentuk final (prefix/check digit, parameter `deposit.account.number_format`)
menunggu pemilik/compliance — dicatat **O-095**. Ditandai di `account.nim`, `MODULE.md`, dan kontrak.

### 3. Tanpa event outbox

Buka rekening hanya menulis audit `deposit.account.open`. Rencana T-088 hanya menyebut event untuk
transaksi tunai/PB (T-088b) dan belum ada konsumen "rekening dibuka"; membuat semantik tanpa pemakai
dihindari (D-095). Dicatat di `MODULE.md`.
