## Scope yang dikerjakan

1. **Migrasi `0004_platform_parameter.sql`** — `platform.param_definition` (value_type,
   json_schema, allowed_scopes, sensitivity, requires_approval, since_version, deprecated) dan
   `platform.param_value` (effective-dated, maker-checker, status DRAFT/PENDING/ACTIVE/
   SUPERSEDED/REJECTED).
2. **Domain `domain/param.nim`** (murni): urutan resolusi dari kernel
   (`PRODUCT → BRANCH → INSTITUTION → SEGMENT → ROLE → GLOBAL`), pemilihan kandidat paling
   spesifik, validasi schema (subset), konversi bertipe (`int64`, `bool`, `string`, `Money`,
   `Rate`, `BusinessDate`, `JsonNode`).
3. **Infra `infrastructure/param_repo.nim`**: baca kandidat pada `as_of`, definisi, submit,
   approve (+ supersede), reject, `missingActiveKeys` (startup check), `LISTEN/NOTIFY`
   (`listenChanges`/`pollChanges`), `submitChange`/`approveChange` (satu transaksi: nilai +
   audit + event `ParamChanged` ke outbox + NOTIFY).
4. **Seed contoh**: `modules/platform/seeds/params.yaml` (3 parameter) + artefak `paramgen`
   yang diregenerasi dan di-commit.
5. **Pengetatan `paramgen`**: `ARRAY[]::text[]` (bug SQL), kunci schema di luar subset ditolak,
   aturan tempat seed pack (lihat keputusan), UUID maker/checker sistem untuk seed pack.

## Keputusan desain

- **Seed pack disemai di scope yang sah saja**: `SEGMENT` (scope_id = nama pack) bila
  diizinkan, selain itu `GLOBAL`; kalau keduanya tidak diizinkan → `paramgen` **gagal** dengan
  pesan jelas (tidak menebak `scope_id` palsu). Konsekuensinya beberapa parameter platform
  menambahkan `GLOBAL` ke `scopes` — itu keputusan pemilik parameter, bukan tool.
- **Baris SUPERSEDED tetap berlaku untuk tanggal lampau.** Saat approve, nilai lama dipangkas
  (`effective_to` = `effective_from` baru) dan ditandai SUPERSEDED; query `as_of` menyertakan
  `ACTIVE` **dan** `SUPERSEDED`. Kalau tidak, tanggal historis kehilangan nilai (gap).
- **EXCLUDE menjangkau ACTIVE + SUPERSEDED** supaya riwayat tidak bisa dibuat ambigu oleh
  aktivasi baru yang menimpa periode lampau.
- **4-eyes berlaku untuk semua parameter**: `checker <> maker` ditegakkan skema. `sensitivity`
  CRITICAL menentukan jenjang approval (T-006), bukan apakah perlu orang kedua.
- **`db_connector.getRow` jebakan**: untuk 0 baris ia mengembalikan Row berisi kolom kosong
  (bukan Row kosong) → "tidak ditemukan" tidak bisa dideteksi dari `row.len`. Repo memakai
  helper `singleRow` berbasis `getAllRows`.
- **Money/Rate/Date = string JSON** (spec §13), bukan angka, supaya presisi desimal tidak
  hilang lewat float JSON.
