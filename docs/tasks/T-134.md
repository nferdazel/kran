# T-134 — Kerangka `daycloser`: registry, state machine, run resumable, status gate deploy

Status: **selesai** 28 Okt 2026 (review independen: lihat §6). Bagian dari Fase 3 (spec §11, §23).
Prasyarat: Fase 0–2 selesai + batch audit A–D (T-126…T-133).

## 1. Lingkup

Membangun **kerangka** orkestrasi penutupan, bukan task bisnisnya (itu T-137/T-138):

1. Registry task saat boot: DAG, penolakan task ganda/level kosong/dependensi tak dikenal.
2. State machine run/task/chunk sesuai spec §11.3 (termasuk pause/cancel/resume).
3. Rencana chunk + checkpoint resumable; chunk sukses tidak diulang.
4. Persistence: `daycloser.run|task|chunk|task_registry|checkpoint` (migrasi `0051`).
5. Retry dengan parameter `daycloser.*`; snapshot parameter dibekukan per run.
6. Advisory lock per scope + unique index satu run aktif per (scope, tanggal).
7. `ctl`: `daycloser-status`, `daycloser-run`, `daycloser-resume`, `daycloser-pause`,
   `daycloser-cancel`; kode keluar status menjadi kontrak gate deploy.
8. Task pertama yang terdaftar: `platform.idempotency_sweep` (menutup T-089/O-094 sebagian).

**Di luar lingkup** (tetap terbuka, lihat §5): freeze/rollover business date (T-135), gate
pre/post (T-136), task ledger/deposit (T-137/T-138), UI monitor (T-139), simulasi 12 bulan +
benchmark (T-140), dry-run/simulation, eksekusi chunk paralel, timeout per task.

## 3. Keputusan yang diambil (detail: D-148)

1. **`CloseLevel` di kernel**, bukan di `daycloser` atau `platform`: dipakai kalender (penentu) dan
   orkestrator (pelaksana), dan kernel mencegah modul saling menembus internal.
2. **Snapshot parameter inline** (`run.param_snapshot jsonb` + hash), bukan FK ke tabel snapshot
   yang belum ada. Isinya konfigurasi efektif `daycloser.*` saat run dibuat.
3. **Satu koneksi per operasi**, bukan satu koneksi sepanjang run: `pool.withConn/withTx` punya
   batas `statement_timeout + margin`; run berjam-jam akan diputus jika koneksinya dipinjam terus.
4. **Chunk dijalankan sekuensial** di proses `ctl`. Paralelisme butuh worker pool + koneksi per
   worker; ditunda ke T-140 bersama benchmark (tercatat di `ACCEPTED-LIMITS`).
5. **Dry-run/simulation belum diimplementasi.** Kolom `mode` sudah ada dan ditolak bila bukan
   `REAL`; menjalankan task nyata di transaksi yang di-rollback butuh desain khusus (task menulis
   lewat pool) — dijadwalkan bersama T-140.
6. **Gate deploy memakai kode keluar**, bukan grep teks: teks operator bisa berubah, kode keluar
   adalah kontrak. Biner lama (belum mengenal perintah) keluar 3 → tetap menahan deploy.
