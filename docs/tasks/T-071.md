## Scope

1. Migrasi `modules/party/migrations/0002_party_kyc.sql` (expand-only, hanya CREATE):
   - `party.identity_doc`: dokumen identitas per party. **Nomor tidak pernah plaintext**:
     `number_enc` = ciphertext field crypto (AAD `identity_doc`), `number_bidx` = blind index
     (HMAC-SHA256, hex) untuk pencarian/duplikat, `number_last2` untuk masking tampilan.
     Unik `(doc_type, number_bidx)` → NIK ganda = 409. `issued_at`/`expires_at` opsional.
   - `party.kyc_profile`: satu baris per party — `status` (PENDING/VERIFIED/REJECTED),
     `risk_level`, `risk_assessed_at`, `next_review_due` (re-KYC periodik, day-close menyusul).
   - `party.risk_rating`: **riwayat append-only** tiap penilaian risiko (level, alasan, oleh, kapan);
     level berjalan = baris terbaru (juga dicerminkan di `kyc_profile`).
2. Domain:
   - `domain/identity.nim`: `parseDocType` (dari daftar parameter), validasi nomor
     (`normalizeDigits` lalu panjang = parameter), `maskNumber` (hanya 2 digit terakhir).
   - `domain/kyc.nim`: `KycStatus`, `parseRiskLevel` (dari daftar parameter), `reviewDueDate`
     (tanggal + bulan dari parameter per level), `newRiskRating`.
3. Parameter baru (seed pack `base`, **bukan kode**; yang compliance-ish ditandai
   `NEEDS-COMPLIANCE-REVIEW`): `party.identity.doc_types`, `party.identity.nik_length`,
   `party.kyc.risk_levels`, `party.kyc.default_risk_level`, `party.kyc.review_months`.
4. Izin baru (`modules/platform/migrations/0014_platform_rbac_party_pii.sql`):
   `party.kyc.manage` (tambah dokumen + nilai risiko) dan `party.identity_doc.read` (membuka nomor
   dokumen = *unmask*). Keduanya diberikan ke `platform_admin`.
5. API (semua lewat `apps/api` sebagai composition root; modul `party` tetap tanpa impor internal
   `platform`):
   - `POST /api/v1/parties/{partyId}/identity-docs` — tambah dokumen. Body tidak pernah
     di-audit/di-log; audit hanya `docType`/`docId`. Duplikat → 409 `identity_duplicate`.
   - `GET /api/v1/parties/{partyId}/kyc` — profil KYC + rating berjalan + riwayat risiko +
     daftar dokumen **tanpa nomor** (hanya `docType`, `last2`, tanggal). Izin `party.party.read`.
   - `POST /api/v1/parties/{partyId}/risk-rating` — penilaian risiko baru: menambah riwayat,
     memperbarui `kyc_profile`, menghitung `next_review_due` dari parameter, audit
     `party.risk.change` + event `party.risk_changed`. Izin `party.kyc.manage`.
   - `POST /api/v1/parties/{partyId}/identity-docs/{docId}/unmask` — body `{reason}` wajib;
     izin `party.identity_doc.read` **di cabang party**, audit `party.identity.unmask` (tanpa nomor,
     tanpa ciphertext). Ini "audit pembacaan" yang diminta spec §18.2 untuk *unmask*.
6. Perilaku saat KEK tidak ada (`KRAN_KEK_FILE` kosong, kondisi produksi sekarang): endpoint
   yang butuh enkripsi/dekripsi menjawab **501** dengan pesan eksplisit (fail-closed, pola MFA
   T-046), bukan 500 atau — lebih buruk — menyimpan plaintext.

## Asumsi (dicatat, bukan ditebak)

- **Blind index = HMAC dengan kunci turunan terpisah** (sudah ada di `platform-lib`), bukan hash
  polos: NIK hanya 16 digit, jadi hash tanpa kunci bisa di-brute-force.
- Nomor dokumen **tidak pernah** masuk audit, event, log, atau respons kecuali endpoint *unmask*
  (izin + alasan + audit). `number_last2` disimpan agar UI bisa menampilkan bentuk tersamar tanpa
  mendekripsi (spec §18.2 "default masked").
- Duplikat dicek **global** antar party (`UNIQUE (doc_type, number_bidx)`), bukan per cabang:
  satu NIK = satu party. Ini yang diminta baris T-071; konsekuensi lintas cabang dicatat di
  `MODULE.md`.
- `party_person`/`party_org`/`address` (nama resmi, tanggal lahir, alamat) **tetap ditunda** ke
  task turunan **T-078**: T-071 fokus dokumen identitas + KYC/risiko supaya diff-nya bisa
  direview manusia (kriptografi) secara utuh.
- `Idempotency-Key` tetap O-072 (repo-wide, belum diputuskan).
- Nilai `party.kyc.review_months`/`risk_levels` adalah **usulan struktur**, bukan angka regulasi:
  ditandai `NEEDS-COMPLIANCE-REVIEW` (spec §1.8, §4 V?).
- Rating risiko di sini **manual** (petugas menilai). Deteksi otomatis dari data transaksi adalah
  lingkup `compliance`/`lending`, bukan T-071.
