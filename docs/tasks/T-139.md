# T-139 — API + UI monitor day-close, tombol manual berizin, dan penjadwal

Status: **rencana** (mulai 28 Okt 2026). Bagian dari Fase 3 (spec §11.7, §16.2).
Prasyarat: T-135 (siklus tanggal), T-136 (gate). Dikerjakan sebelum T-138.

## 1. Masalah

Sampai T-137, penutupan hanya bisa dijalankan lewat `ctl` di server: tidak ada status yang bisa
dilihat operator, tidak ada riwayat, tidak ada tombol resume setelah `BLOCKED`, dan pemicu harian
masih manual (O-094). Spec §11.7/§16.2 meminta monitor progres, aksi (resume/cancel), dan pemicu
terkontrol parameter; `ACCEPTED-LIMITS` mencatat bahwa endpoint `dayclose` HTTP akan **terblokir**
gerbang `CLOSING` bila tidak ditambahkan ke pengecualian.

## 2. Lingkup (tiga commit terpisah)

### 2a. API baca + aksi

| Endpoint | Isi |
|---|---|
| `GET /api/v1/dayclose/status` | tanggal buku (tanggal, state, waktu beku) + run aktif (kalau ada) + ringkasan run terakhir per tanggal |
| `GET /api/v1/dayclose/runs?limit=` | riwayat ringkas: tanggal, level, state, mulai/selesai, jumlah task ok/gagal/lewati |
| `GET /api/v1/dayclose/runs/{runId}` | detail: task + chunk (state, attempt, error code, metrics), ringkasan, segel |
| `POST /api/v1/dayclose/run` | jalankan penutupan tanggal buku berjalan (`--business-date` default = tanggal buku) |
| `POST /api/v1/dayclose/runs/{runId}/resume` | lanjutkan run `PAUSED`/`FAILED`/`BLOCKED` |
| `POST /api/v1/dayclose/runs/{runId}/pause` | hentikan di batas chunk |
| `POST /api/v1/dayclose/runs/{runId}/cancel` | batalkan + buka kembali tanggal (atomik, T-135) |

Aturan yang dipegang:

- **Izin**: `dayclose.run.read` (status/riwayat/detail) dan `dayclose.run.manage` (aksi). Seed di
  migrasi RBAC + role admin/operasional; bukan string bebas di handler.
- **Pengecualian gerbang `CLOSING`**: hanya `/api/v1/dayclose/` (persis, dengan garis miring
  penutup) — aksi resume/cancel **harus** bisa dipakai justru saat `CLOSING`. Pengecualian tetap
  menuntut sesi + izin; gerbang hanya melewati penolakan 409. Gate kontrak `topenapi` diperbarui
  agar pengecualiannya satu definisi dengan runtime (kini dua: `/api/v1/auth/` dan
  `/api/v1/dayclose/`).
- **Audit**: setiap aksi menulis audit dengan aktor pengguna (bukan `device = ctl`) dan alasan
  opsional dari badan permintaan.
- **Idempotensi**: `run`/`resume`/`cancel` menerima `Idempotency-Key` (jalur yang sudah ada), supaya
  klik ganda tidak menjalankan dua penutupan.
- **Konkurensi**: aksi memakai advisory lock yang sama dengan `ctl`; dua operator tidak bisa
  menjalankan dua run untuk scope yang sama.

### 2b. Penjadwal harian

- Perintah baru `ctl daycloser-auto`: membaca parameter `daycloser.auto.enabled` (bool, default
  `false`) dan `daycloser.auto.run_at` (`HH:MM`, zona waktu institusi); bila aktif dan belum ada run
  untuk tanggal buku berjalan dan waktunya sudah lewat → jalankan penutupan yang sama dengan
  `daycloser-run`. Keluaran tetap memakai kode `ctl` (0 = tidak ada yang perlu dikerjakan/selesai,
  1 = run tidak selesai, 3 = ditolak).
- Berkas unit systemd (timer + service) di `ops/systemd/` sebagai cermin konfigurasi server; **tidak**
  dipasang oleh agent (butuh akses server) — operator memasang, runbook mencatat langkahnya.
- Penjadwal **tidak** dijalankan di dalam proses worker `ledger`: worker memompa outbox, dan
  penutupan yang berjalan di proses yang sama akan menahan posting yang justru dibutuhkan gate.

### 2c. UI `/app/dayclose`

- Halaman monitor: status tanggal buku, kartu run aktif (progres per task + chunk, kode galat,
  metrik bukti), riwayat, tombol Jalankan/Resume/Pause/Cancel dengan konfirmasi.
- Progres: pakai kanal realtime yang sudah ada (`events.nim`) bila memuat kejadian
  `daycloser.*`; jatuh tempo aman ke polling 2–3 detik selagi run aktif.
- i18n id+en lengkap (tidak ada string hardcode), nomor/uang lewat formatter yang ada.
- a11y: axe 2 tema × 2 locale, keyboard-only untuk alur utama (jalankan → lihat progres → resume),
  status tidak hanya lewat warna.

## 4. Kriteria selesai

- [ ] Endpoint baca status/riwayat/detail dan aksi berizin, terdaftar di kontrak, klien TS sinkron.
- [ ] Aksi bisa dipakai saat `CLOSING` (pengecualian sempit), tetap menolak tanpa sesi/izin.
- [ ] Setiap aksi menulis audit dengan pelaku pengguna; `Idempotency-Key` mencegah run ganda.
- [ ] Tidak ada logika penutupan baru di handler: handler memanggil jalur yang sama dengan `ctl`.
- [ ] Penjadwal `daycloser-auto` menghormati parameter (mati = tidak melakukan apa pun) dan tidak
      menabrak run yang sedang berjalan.
- [ ] UI: monitor + aksi, progres terlihat, i18n id+en, axe 2 tema × 2 locale, keyboard-only.
- [ ] `./task ci` hijau; `ACCEPTED-LIMITS`/`O-094` diperbarui.

## 5. Di luar lingkup

Penutupan per cabang (scope `BRANCH`), `mode=SIMULATION` (dry-run §11.7), dan pemasangan unit
systemd di server (butuh akses operasi).
