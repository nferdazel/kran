# T-097 — Perkuat test race: dua aktor checker, bukan dua request satu token

Status: **implemented, menunggu test DB + CI** (branch `feat/fase2`). Turunan MINOR review T-091.

## Lingkup

Test balapan dua checker di `apps/api/tests/itapi_product.nim` dulu memakai **satu token** untuk dua
request, jadi yang diuji hanya balapan dua request — bukan dua aktor. Perbaikan: pakai dua aktor
berbeda dan buktikan `checker` tercatat atas aktor pemenang. **Tidak ada perubahan perilaku
produksi.**

## Perubahan (`apps/api/tests/itapi_product.nim` saja)

- Fixture seed uji: tambah user `dev.approver2` (salin hash kata sandi dari `dev.checker`, sama
  seperti `dev.approver`) + grant role `platform_admin`. **Hanya di berkas test**, bukan pack
  produksi (`packs/base/seed`).
- `approver2Token` login kedua.
- Suite `product: balapan dua checker`: thread slot 0 memakai token `dev.approver`, slot 1 memakai
  token `dev.approver2`.
- Assert baru: `checker` pada `product.product_version` sama dengan `user_id` **aktor pemenang**
  (slot yang menerima `200`), bukan sembarang approver. Yang kalah tetap `409 not_draft` dan tidak
  menambah audit/event kedua (assert lama tetap).

## Bukti (tanpa DB)

```
nim check --threads:on apps/api/tests/itapi_product.nim   → bersih
nimpretty --stdin diff apps/api/tests/itapi_product.nim   → format-clean
```

## Sisa yang butuh DB / CI

- `./task test itapi_product` (butuh PostgreSQL; balapan dua aktor + assert `checker`).
- `./task ci`.

Catatan: test tetap menahan baris versi (`SELECT ... FOR UPDATE`) supaya kedua request benar-benar
terblokir di guard `UPDATE ... WHERE status = 'DRAFT'`, bukan hanya berurutan karena penjadwalan.
