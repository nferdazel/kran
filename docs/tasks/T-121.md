# T-121 — UI pengajuan & persetujuan top-up vault (`/app/vault`)

Status: DONE (24 Okt 2026). Rujukan: `docs/BACKLOG.md` T-121, D-132 (maker-checker + jurnal), D-133
(plafon), D-134 (K-4 format bukti, K-8 larangan `teller`).

## Scope

Layar operator untuk siklus top-up kas vault: lihat saldo, ajukan, setujui, tolak. Backend sudah
lengkap sejak T-118 (`teller/0035`); task ini hanya menambah **permukaan** dan satu kebutuhan
kecil yang menghalanginya: daftar cabang belum punya jalur HTTP (O-101), sehingga operator harus
menebak UUID.

Masuk:
- `GET /api/v1/branches` (baca saja) + izin `platform.branch.read` (`platform/0037`).
- Halaman `/app/vault`: pemilih cabang, saldo vault, form pengajuan (maker), daftar pengajuan +
  setujui/tolak (checker), state kosong/memuat/galat, i18n id+en, navigasi.
- `lib/app/vault.ts` (logika murni: validasi, pemetaan galat, kunci idempotensi) + unit test.
- e2e `vault.spec.ts`: ajukan sebagai `ops_admin`, setujui sebagai `cash_admin` lain, saldo naik.
- Seed dev: dua akun kas berbeda (`dev.cashmaker`, `dev.cashchecker`), keduanya `cash_admin`.

Tidak masuk:
- Tulis master cabang (buat/ubah cabang) — tetap `ctl create-branch`.
- Keputusan plafon tambahan (akumulasi harian, plafon saldo vault, toleransi variance).
- Perubahan aturan maker-checker/jurnal: handler dan migrasi teller tidak disentuh.

## Kontrak yang dipakai

| Rute | Izin | Catatan |
|---|---|---|
| `GET /api/v1/branches` | `platform.branch.read` | baru; `{items:[{branchId,code,name,status}]}` |
| `GET /api/v1/teller/vault?branchId=` | `teller.vault.read` | 404 `vault_not_configured` |
| `GET /api/v1/teller/vault/topups?branchId=&status=&limit=` | `teller.vault.read` | `status` opsional |
| `POST /api/v1/teller/vault/topups` | `teller.vault.submit` | `Idempotency-Key`; 409 `topup_exceeds_limit`, `source_account_invalid`, `topup_request_conflict` |
| `POST .../topups/{id}/approve` | `teller.vault.approve` | 409 `self_approval`, `topup_request_not_pending` |
| `POST .../topups/{id}/reject` | `teller.vault.approve` | body `{reason}` wajib |

## Catatan implementasi

- **Daftar cabang** (`GET /api/v1/branches`): izin `platform.branch.read`; handler memakai
  `requirePermission` saja (bukan `authorizedAtBranch(..., "")`) karena pemegang role `BRANCH`
  adalah pengguna yang paling butuh daftar itu. Tidak ada rute tulis.
- **Izin di layar**: menu memakai `teller.vault.read`; form tampil dengan `teller.vault.submit`,
  tombol keputusan dengan `teller.vault.approve`. Pemegang baca-saja mendapat satu kalimat
  penjelasan, bukan tombol mati.
- **Seed dev**: `dev.cashmaker`/`dev.cashchecker` keduanya `cash_admin` (dua akun) dan sengaja bukan
  `ops_admin`, supaya jumlah pemegang `platform.user.manage` di seed tidak menggeser uji
  "pengelola terakhir" (`itapi_users`).
