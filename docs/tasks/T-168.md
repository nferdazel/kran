# T-168 — Restrukturisasi & hapus buku

**Status**: DONE (2 Nov 2026) · **Keputusan**: D-186 (lima jawaban pemilik 1 Nov 2026) · **Deps**: T-167

## Keputusan yang dipakai (bukan ditebak)

Spec hanya menyebut "restrukturisasi, hapus buku" sebagai cakupan modul (§4 baris 88) dan
`WRITTEN_OFF` sebagai status. Lima pertanyaan diajukan ke pemilik dan dijawab 1 Nov 2026; semuanya
dicatat di **D-186**:

| Pertanyaan | Jawaban |
|---|---|
| Bentuk restrukturisasi | **Jadwal versi baru**, jadwal lama diarsipkan (`superseded_on`) |
| Tunggakan bunga/denda | **Dilepas**, dasar jadwal baru = sisa **pokok** |
| Kolektibilitas pasca-restrukturisasi | **Kembali lancar** (DPD dari jadwal aktif) — `NEEDS-COMPLIANCE-REVIEW`, O-123 |
| Syarat & nilai hapus buku | `ACTIVE` + golongan **`LOSS`**, hapus **seluruh sisa kewajiban** |
| Jurnal hapus buku | `D 111` sebatas penyisihan, sisanya `D 504` (akun baru), `K 110` |

## Scope yang dikerjakan

1. **Skema** (`lending/0093`, `lending/0094`): `installment.schedule_version` + `superseded_on`,
   tabel `lending.loan_schedule` (versi jadwal, backfill versi 1), kolom `written_off_on/by/reason`
   + CHECK yang memaksa jejak lengkap, tabel `lending.writeoff` (rincian nilai + penyisihan terpakai).
2. **Ledger** (`ledger/0095`): akun `504 BEBAN HAPUS BUKU`, rule `LoanWriteOffProvisioned`
   (D 111 / K 110) dan `LoanWriteOffExpense` (D 504 / K 110).
3. **RBAC** (`platform/0096`): `lending.loan.restructure` (maker + admin),
   `lending.loan.write_off` (checker + admin — **bukan** maker).
4. **Domain** (`restructure.nim`, `writeoff.nim`): jadwal versi baru dengan nomor lanjutan; pembagian
   penyisihan vs beban dengan invarian `allowanceApplied + expense == total`.
5. **HTTP**: `POST /lending/loans/{id}/restructure` dan `POST /lending/loans/{id}/write-off`, keduanya
   `Idempotency-Key` wajib, audit + event (`LoanRestructured`, `LoanWrittenOff`).
6. **PPAP**: pemeriksaan "penyisihan menggantung" (`DAY-384`) sekarang membandingkan penyisihan
   terakhir dengan `writeoff.allowance_applied`, jadi hapus buku tidak menggagalkan penutupan buku.

## Invarian yang diuji

- Restrukturisasi: jadwal lama **tidak berubah** (kewajiban & `paid_*` beku), jadwal baru = sisa pokok
  tepat, nomor angsuran berlanjut, pembayaran berikutnya hanya menyentuh baris aktif, replay kunci
  tidak membuat versi kedua.
- Hapus buku: `allowanceApplied + expense == total`, kredit `110` sebesar nilai yang dihapus, sisi
  tidak pernah negatif, saldo pinjaman nol, jejak (tanggal/pelaku/alasan) terisi, replay tidak
  menjurnal dua kali.
- Kolektibilitas: tunggakan jadwal **arsip** tidak lagi dihitung sebagai DPD (restrukturisasi
  mengembalikan golongan ke lancar).

## Non-goals (dicatat sebagai batas)

- **Pemulihan pasca hapus buku** (O-122): `WRITTEN_OFF` tidak menerima pembayaran.
- Restrukturisasi **tidak mengubah tarif/metode** (selalu dari versi produk).
- Penjualan agunan, asuransi/klaim, dan rumus denda keterlambatan (D-180 belum menetapkannya).
