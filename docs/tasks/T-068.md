# T-068 — `rollback.sh` sadar container (T-067)

Status: **DONE** (19 Okt 2026). Terkait: D-066.

## Masalah

Setelah layanan menjadi container quadlet (T-067), `ops/scripts/rollback.sh` masih menyalin
`bin/kran-api.prev` → `bin/kran-api` lalu me-restart unit. Container **tidak** membaca biner host;
yang dipakai adalah image `localhost/kran-api:local`. Jadi skrip itu bisa mencetak
"rollback selesai" sementara layanan tetap menjalankan image yang gagal — sukses palsu pada jalur
mundur darurat.

## Rencana

- Rollback = `podman tag localhost/kran-api:prev localhost/kran-api:local`.
- Tolak jalan bila unit quadlet tidak ada atau unit native bernama sama masih ada (penyebab insiden
  cutover, D-066 butir 3).
- Pulihkan `web.prev`, unit `.container.prev`, dan biner gate (`bin/kran-api.prev`) bila ada.
- Setelah restart, poll `/readyz` ×15 (sama dengan deploy); tidak sehat → exit 1.
- Tidak menyentuh DB (tetap seperti sebelumnya).

## Bukti

Harness lokal (stub `podman`/`systemctl`/`curl`/`sleep`, `KRAN_APP_DIR`/`KRAN_UNIT_DIR`/`HOME`
diarahkan ke direktori sementara; skrip tidak dijalankan di server):

| Skenario | Hasil |
|---|---|
| Jalur bahagia | `podman tag :prev :local`, biner gate/web/unit `.prev` pulih, `daemon-reload` + 2 restart, `/readyz` stub ok → exit 0 |
| Image `:prev` tidak ada | exit 1, **tanpa** restart |
| Unit native `kran-api.service` ada | exit 1, tanpa menyentuh apa pun |
| `/readyz` tidak sehat | exit 1 setelah 15 poll |

**Diskriminatif:** skrip **lama** dijalankan pada keadaan "`:prev` tidak ada" → **exit 0**,
mencetak "rollback selesai", dan log panggilan hanya berisi dua `systemctl restart` (tidak ada
`podman tag`). Jadi harness benar-benar membedakan perilaku lama vs baru.

`bash -n` + `shellcheck -S warning` bersih (gate `./task check`).

## Sisa jujur

Belum pernah dijalankan di produksi. Rollback otomatis di `deploy-vps.sh` sudah memakai model yang
sama (tag `:prev` + `restore_units`); skrip manual ini menyamakan langkahnya, bukan menggantinya.
