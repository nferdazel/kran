# T-135 — Siklus business date: freeze, tutup, rollover, dan gerbang transaksi

Status: **selesai** 28 Okt 2026. Bagian dari Fase 3 (spec §11.2, §11.5, §9.3).
Prasyarat: T-134 (kerangka `daycloser`).

## 1. Lingkup

Menutup celah antara "run selesai" dan "tanggal buku maju", plus konsekuensinya bagi transaksi
daring:

1. **Freeze** `OPEN → CLOSING` setelah seluruh task `PRECHECK` lulus, sebelum task proses pertama.
2. **Seal**: `CLOSING → CLOSED` + **rollover** ke hari kerja berikutnya (`OPEN`) + event
   `BusinessDateOpened`, dalam **satu transaksi** dengan `run → COMPLETED` dan audit `run.finish`.
3. **Abort**: run yang dibatalkan membuka kembali tanggal yang dibekukannya (`CLOSING → OPEN`),
   karena belum ada segel — bukan reopen EOD.
4. **Gerbang transaksi**: selama `CLOSING`, perubahan lewat HTTP ditolak `409
   business_date_closing`, kecuali rute autentikasi dan kecuali parameter
   `daycloser.txn_policy_during_close = ALLOW`.
5. **Bootstrap tanggal buku** eksplisit (`--bootstrap`) dan penolakan tanggal yang bukan tanggal
   buku berjalan.

Di luar lingkup: penjadwal harian & UI monitor (T-139), task bisnis (T-137/T-138), penutupan per
cabang, kebijakan `QUEUE` (antrean transaksi) yang belum punya eksekutor.

## 3. Keputusan (detail: D-149)

1. **Tanggal buku dimiliki run, bukan operator.** `daycloser-run` membekukan tanggalnya sendiri;
   tidak ada perintah `freeze` terpisah yang bisa lupa dipanggil.
2. **Seal + rollover satu transaksi.** Run `COMPLETED`, tanggal `CLOSED`, tanggal baru `OPEN`, dan
   event `BusinessDateOpened` tidak bisa terpisah oleh crash.
3. **Abort khusus `CLOSING → OPEN`.** Tanpa itu, satu run yang dibatalkan membekukan institusi
   selamanya. `CLOSED` tetap tidak bisa dibuka (spec §11.7).
4. **Gerbang di pembungkus HTTP**, bukan per handler: rute baru tidak bisa lupa. Fail-open hanya
   saat basis data tidak terbaca (permintaan itu akan gagal sendiri); parameter kebijakan yang
   hilang/rusak fail-closed.
5. **Bootstrap eksplisit.** Tanggal buku pertama hanya dibuat dengan `--bootstrap`; tanpa itu
   `ctl` menolak, sehingga salah ketik tidak menetapkan tanggal buku yang salah untuk selamanya.
6. **Cancel langsung bila tidak ada proses.** `daycloser-cancel` memeriksa advisory lock: bila
   tidak ada proses hidup, perintah diterapkan saat itu juga (bukan menulis niat yang tak dibaca).

## 5. Batas yang dicatat

| Batas | Dampak | Deteksi | Pemilik |
|---|---|---|---|
| Kebijakan `QUEUE` tidak ada | Spec menyebut "ditolak/antri"; hanya `REJECT`/`ALLOW` yang sah | `parseTxnPolicy("QUEUE")` → error | T-139/T-140 (butuh antrean + worker) |
| Penutupan per cabang belum diekspos | `ctl` hanya `INSTITUTION`; run cabang ditolak tegas | `assertInstitutionRun` | T-139 |
| Gerbang menambah satu query per permintaan tulis | Latensi kecil (indeks `business_date_state_idx`); bukan cache | ukur di T-140 | T-140 |
| Fail-open saat DB tak terbaca | Perubahan bisa lolos bila *hanya* query gerbang yang gagal | log `gerbang penutupan tidak dapat memeriksa basis data` | Operasi (dinilai aman: handler akan gagal sendiri) |
| Guard tidak menutup jalur non-HTTP (worker/ctl) | Proses internal tetap bisa menulis saat CLOSING | — | by design |
| Belum ada penjadwal harian | `daycloser-run` tetap dipicu operator | O-094 | T-139 |

## 6. Review independen

Reviewer dengan konteks bersih (tanpa alasan penulis): **1 BLOCKER, 2 MAJOR, 5 MINOR, 3 NIT**.
Verdict awal `CHANGES REQUIRED`; semua BLOCKER/MAJOR diperbaiki, MINOR yang murah ikut diperbaiki.

| Temuan | Tindakan |
|---|---|
| **BLOCKER** — setelah `daycloser-cancel`, tanggal itu tidak pernah bisa ditutup lagi (`runCmd` menolak run apa pun untuk tanggal tersebut, `resume`/`cancel` menolak `CANCELED`) | `runCmd` mengizinkan run baru bila run lama `CANCELED` (index unik DB memang mengecualikannya); test integrasi baru `tanggal yang run-nya dibatalkan bisa ditutup lagi` membuktikan tanggal maju.
