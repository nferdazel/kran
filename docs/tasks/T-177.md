## Scope

Decide, in writing and before wiring anything, what a red dependency result means:

1. Which scanner runs (a `pnpm audit` style registry check, or an offline advisory database), and
   whether it can run in CI without a network dependency that flakes.
2. What fails the gate: a severity floor, and whether it fails on every finding or only on
   findings the allowlist does not cover. `docs/SECURITY.md` already forbids making an
   advisory-only scan a deploy gate without deciding what a red result means — this task is that
   decision, recorded in `docs/DECISIONS.md`.
3. The Nim side: `kran.nimble` has no lockfile. Either add one and prove two builds of the same
   commit resolve identically, or record the gap as an accepted limit with the reason. Do not
   invent a lock format the toolchain does not support.

Then wire it: a `deps-check` arm in `task`, one CI step or job following the golden CI contract
(timeout, cache, no context interpolation inside `run:`), and the SECURITY.md rows updated to say
what is now covered and what is still not.

Out of scope: bumping any dependency to clear a finding (that is a separate change with its own
review), pinning GitHub Actions to commit SHAs (`SEC-06`, separate workflow review), and adding a
scanner that cannot run in CI.

## Acceptance

1. `./task deps-check` on the clean tree exits 0 and prints what it scanned and against which
   advisory source.
2. Seeded red: add one package with a known critical advisory to `pnpm-lock.yaml` (or a synthetic
   finding the tool's own fixture supports) → the arm exits 1 and names the package and advisory.
   The seed is reverted before commit, and the raw output is in the report.
3. Missing tool: with the scanner unavailable, the arm fails closed and says how to install it; it
   does not print a skip line and exit 0 (the T-176 rule, applied here).
4. CI: the job or step runs on a pull request and on `main`, has `timeout-minutes: 15`, and passes
   context through `env:` rather than shell interpolation.
5. `docs/SECURITY.md` G5 row and the policy text match what is actually wired; `docs/DECISIONS.md`
   carries the red-result decision.
6. `./task check-fast` stays 8/8 and `./task ci-fast` green.

## Notes

The cheapest honest outcome is allowed here: if the only tool that works in this CI cannot cover
Nim, say so in SECURITY.md rather than pretending the Nim tree is scanned. A gate that covers npm
and GitHub Actions and says so is worth more than one that claims full coverage.
