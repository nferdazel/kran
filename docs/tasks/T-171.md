# T-171 — Laporan pinjaman: tunggakan/aging, PPAP, rekonsiliasi

**Status**: DONE (2 Nov 2026) · **Deps**: T-167

## Kenapa tiga laporan, bukan satu

Yang diminta sama: "angka cocok dengan subledger pada fixture tetap". Yang berbeda: **tanggal
acuannya**.

- Tunggakan dan PPAP adalah potret **per tanggal buku** (`asOf`): keduanya dibaca dari snapshot
  harian T-166/T-167, dan laporan untuk tanggal lampau harus memakai nilai tanggal itu, bukan nilai
  hari ini.
- Rekonsiliasi membandingkan GL dengan subledger **saat ini**. Menaruhnya di endpoint `asOf` akan
  mencampur "saldo GL per 30 Juni" dengan "sisa pokok hari ini" — selisihnya bukan temuan, hanya
  dua tanggal berbeda di satu kertas.

## Scope

1. `GET /api/v1/lending/reports/arrears?asOf=` — per pinjaman: DPD, golongan, tunggakan
   pokok/bunga/denda; total; agregat **per golongan** (itulah aging DPD).
   Sumber tunggakan = `lending.installment` (baris aktif, `due_on < asOf`), bukan cache
   `loan_balance`: cache bisa tertinggal dan laporan harus bisa menjelaskan angkanya.
2. `GET /api/v1/lending/reports/allowance?asOf=` — per golongan: jumlah pinjaman, dasar, tarif,
   penyisihan (`lending.ppap_snapshot` tanggal itu) + total.
3. `GET /api/v1/lending/reports/reconciliation` — saldo GL `110`/`111` versus subledger
   (`loan_balance.principal_outstanding`, penyisihan terakhir per pinjaman, penyisihan terpakai hapus
   buku) + selisih. Identitasnya: `GL 110 = Σ sisa pokok` dan
   `GL 111 = Σ penyisihan terakhir − Σ allowance_applied`.
4. Zona waktu/tanggal: `asOf` default = tanggal buku institusi (pola handler lain); `asOf` tidak sah
   → 400.
5. Izin `lending.loan.read` pada tingkat institusi (pola laporan `ledger`): laporan agregat lintas
   cabang tidak diberikan ke pemegang izin satu cabang.
6. OpenAPI + kontrak klien TS; test integrasi memakai fixture tetap (satu pinjaman dicairkan,
   dibayar sebagian, diregrade, disisihkan) dan membandingkan angka laporan dengan subledger +
   GL.
