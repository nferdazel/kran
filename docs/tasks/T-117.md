# T-117 — Administrasi pengguna & peran lewat API + UI

Status: **DONE** (24 Okt 2026) — PR #9. **HUMAN-REVIEW-REQUIRED** (authz/administrasi pengguna).

## Scope

Sebelumnya hanya `ctl` yang bisa membuat/mengelola akun operator (O-103). T-117 memberi jalur
HTTP + layar dengan **aturan yang sama**, bukan kebijakan kedua.

1. **Migrasi** `platform/0029`: izin `platform.user.manage` (module platform, resource user,
   action manage) + grant eksplisit ke `platform_admin`. Idempotent (pola 0008/0022–0028).
2. **Kebijakan dipusatkan**: `grantUserRole`, `revokeUserRole`, `disableUserAccount`,
   `enableUserAccount`, `unlockUserAccount`, `locksOutLastAdmin` di `auth_service`; `main.nim`
   (ctl) memakai fungsi yang sama. Audit action/payload identik dengan ctl.
3. **Rute** (gerbang ganda: `requirePermission` + `authorizedAtBranch(..., "")`):
   - `GET /api/v1/users` — limit 20/maks 200, tanpa hash kata sandi/secret.
   - `GET /api/v1/roles` — kode, scope, isSystem.
   - `POST /api/v1/users/{userId}/roles` `{role, branchId?}`.
   - `DELETE /api/v1/users/{userId}/roles/{role}?branchId=` (grant persis).
   - `POST /api/v1/users/{userId}/disable|enable|unlock`.
   - Problem membawa `params.reason`: `role_scope`, `role_not_found`, `sod_conflict`,
     `already_granted`, `not_granted`, `last_admin`, `not_inactive`, `not_locked`,
     `user_not_found`.
4. **Web** — `/app/users` bergate `platform.user.manage`: tabel pengguna (username, nama, status,
   badge role), panel kelola inline (assign role + cabang saat scope BRANCH, revoke,
   disable/enable/unlock dengan konfirmasi inline). Tanpa `window.confirm`; state
   loading/empty/error/denied; i18n id+en.

Tidak masuk: perubahan makna guard "admin terakhir" (masih menghitung semua grant, sama seperti
ctl).
