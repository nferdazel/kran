# T-040 — Setup deploy key + webhook di server (user `sachiel`)

Status: DONE
Prioritas: P2 (prasyarat deploy; dipisah dari T-039 karena menyentuh server)

## Kenapa
Repo sudah bernama KRAN dan seluruh identifier ikut (D-039). Deploy belum pernah terpasang: T-013
hanya menulis *berkas* ops di repo, belum menyentuh server. Dua hal hanya bisa dipasang di server —
deploy key (kredensial) dan hook webhook — jadi keduanya dikerjakan di task terpisah yang mencatat
apa yang diubah di luar repo.

## Yang dipasang
- **Deploy key** baru khusus repo ini: `~/.ssh/kran_deploy` (ed25519, dibuat **di server**; kunci privat
  tidak pernah meninggalkan server) + alias `github-kran` di `~/.ssh/config` (`~/.ssh/config`
  dicadangkan sebelum diubah). Terdaftar di GitHub sebagai deploy key **read-only** (id `166514836`,
  judul `vps-read-only`).
- **Hook webhook `kran`** di `/srv/qouver/config/webhook.json` (berkas dicadangkan lebih dulu):
  `payload-hmac-sha256` + header `X-Hub-Signature-256`. Lima hook lama memakai sha1; spec §21.7 meminta
  jangan mewarisinya. Perintah `/srv/qouver/apps/kran/scripts/deploy-vps.sh`, argumen
  `repository.name` + `ref` — sama seperti pola `sds-monorepo`.
- **Drop-in systemd** `~/.config/systemd/user/webhook.service.d/kran.conf`:
  `KRAN_GIT_URL=github-kran:nferdazel/kran.git` (pola sama dengan `skyward.conf`).
- **Hook di GitHub**: id `698395667`, `events: ["push"]`, `content_type: json`, `insecure_ssl: "0"`,
  url `https://api.qouver.com/hooks/kran`.

## Bukti
- `ssh -T github-kran` **dari server**: `Hi nferdazel/kran! You've successfully authenticated, but
  GitHub does not provide shell access.` — deploy key bekerja dan cakupannya repo itu saja.
- Uji lokal dengan **tanda tangan benar** (HMAC-SHA256 dihitung di server, bukan tebakan): **HTTP 200**,
  log `kran got matched` + `kran hook triggered successfully`, lalu
  `error in exec: "/srv/qouver/apps/kran/scripts/deploy-vps.sh": no such file or directory`. Itu bukti
  wiring benar **sekaligus** bukti deploy belum mungkin jalan.
- Uji dengan **tanda tangan salah**: **HTTP 500**, log `invalid payload signatures [deadbeef]` — jadi
  meski repo remote publik, orang lain tidak bisa memicu deploy tanpa secret. (Penolakan muncul sebagai
  500, bukan 406 — berguna saat membaca riwayat delivery di GitHub.)
- Setelah restart: `systemctl --user is-active webhook.service` = `active`; 6 hook terbaca
  (`sds-monorepo`, `cbs-core`, `majadu-monorepo`, `fond`, `skyward`, `kran`) — lima lama tidak berubah.

## Yang dibiarkan, dan alasannya
- **Lima hook lama tidak disentuh**, termasuk yang masih sha1: mengubahnya adalah perubahan pada sistem
  lain, bukan efek samping task ini.
- `/srv/qouver/apps/cbs`, kunci `cbs_deploy`, alias `github-cbs`, dan hook `cbs-core` milik
  `nferdazel/cbs-core` (sistem lama yang masih berjalan) — dibuktikan dari `git remote -v` clone di
  server, bukan diasumsikan dari namanya yang mirip.
- **Secret tidak pernah masuk repo dan tidak pernah dicetak**: dibuat di server, disalin ke berkas
  sementara hanya untuk mendaftarkan hook ke GitHub, lalu berkas sementaranya dihapus.
- `/srv/qouver/apps/kran` **belum dibuat** dan skrip deploy belum dipasang — itu bagian latihan deploy
  (T-013), yang juga butuh DB produksi + berkas env. Selama belum, push ke `main` hanya menghasilkan
  galat `no such file or directory` di webhook: gagal bersih, tidak ada efek.

## Yang belum
- Latihan `deploy-vps.sh` manual di server (T-013) — syarat sebelum push pertama ke `main`.
- Repo remote `nferdazel/kran` masih **kosong** (0 ref) dan **publik**. Dua konsekuensi yang perlu
  keputusan pemilik: (a) deploy key sebenarnya redundan untuk repo publik (tetap dipakai karena polanya
  konsisten); (b) kode core banking ada di repo publik — keputusan visibilitas ada di tangan pemilik.
