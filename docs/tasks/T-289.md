## Scope

The table states the currency once, in the column header. Cells render the number only, right
aligned, `nowrap`, `tabular-nums slashed-zero`. Negative amounts always carry a leading minus,
never parentheses, and the same convention holds across every table; colour is never the only
signal. A column reserves the width of its widest value so a value growing from 3 to 7 digits does
not move the neighbouring columns.

In scope, because it is the second path to a per-cell unit: remove the `currency` prop from
`packages/ui/src/components/Money.svelte`. After that the component renders identical output for
every caller, because there is no prop left to ask with and the currency lives in the column label.

Deliberately not in scope: any change to `formatMoney` arithmetic or rounding, any backend or
contract change, per-row currency (the domain has one currency per table).

Out of scope, explicitly (Sekar, 2026-11-10): the normal-balance rule for money columns - member
savings are a liability of the cooperative and loan outstanding is an asset, so neither is ever
rendered as a negative, and a negative balance is an invariant violation that must surface as an
abnormal state or a red test, not as tidy `-1.500,00`. That rule lives at the page/report level,
not in `DataTable`, because a generic component cannot know which column is a liability. It is a
separate small ticket after P6, not part of T-289.

## Acceptance

New cases fail on the parent commit because the header-only symbol and the negative convention do
not exist there:

1. A numeric column labelled `Saldo (IDR)` renders no currency text in any cell; a rendered cell's
   text matches the number pattern only. Asserting the reverse (symbol present in a cell) fails.
   `Money` renders identical output for every caller because the `currency` prop no longer exists.
   The existing per-cell currency test (`currency hanya diumumkan, bukan diulang di tiap sel` in
   `packages/ui/tests/components.test.ts`) is replaced in the same commit by a header-only case,
   not deleted - deleting it would drop a capability.
2. The same `formatMoney` output is used for display and for the assertion - the test reads the
   expected string from `formatMoney`, not from a hand-written literal, so a formatting change
   cannot silently pass.
3. A negative value renders a leading `-` and never `(` or `)`; the same case asserts zero
   parenthesis characters in the cell text; and no second formatter exists
   (`rg 'export function format' packages/ui/src/money.ts` returns exactly one hit). The number
   stays in normal ink: colour is never the only signal. This test must be red on the parent
   commit, not only green on the ticket commit - a test that already passes on the parent proves
   nothing (Sari, 2026-11-10).
4. A column with 3-digit and 7-digit values renders both cells with the reserved width class; the
   test asserts the class is present, the visual proof is a manual check at 100% and 200% zoom.

Because this is a `money` task, an independent reviewer reads the diff before merge. Human review is
not required: no arithmetic is added or changed.
