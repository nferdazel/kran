## Scope

Two new presentational components and one changed one:

- `LoadingState` - `role="status"` plus `aria-busy` on the region it replaces; `<screen>_loading`.
- `ErrorState` - title, body, retry label; retry is `app_retry` ("Coba lagi"), never `Muat ulang`.
- `EmptyState` gains `kind`: `no-data` (teaches the first action), `no-match` (caller passes
  `common_filter_clear` as the action), `denied` (names the permission and who grants it). Three
  kinds, three sentences, never one sentence for all. The component stays presentational: it does
  not look up copy, it renders the sentence and action the caller gives it.

Keys in this ticket, and nothing else:

| Key | Change |
|---|---|
| `loans_empty` | rewrite to no-data: "Belum ada pinjaman. Ajukan pinjaman pertama." |
| `loans_empty_no_match` | new, takes today's no-match value |
| `ledger_empty` | rewrite: the screen shows balances, not journals |
| `ledger_filter_empty` → `ledger_empty_no_match` | rename, copy unchanged |
| `vault_empty_no_match` | new, `{status}` receives the translated label, never the enum |
| `common_filter_clear` | new: "Hapus filter" / "Clear filter" |

Terminology: id copy says **Kas besar** and **Kasir**; en keeps "Cash vault" and "Teller"; code
identifiers keep `vault` / `teller`. This ticket fixes every id value that still says vault or
teller - 24 values by the repository grep, keys unchanged - because changing two nav labels and
leaving 22 operator sentences is the same bug with a smaller diff.

Deliberately not in scope: `ledger_empty_hint` (it needs a period action and waits on the period
control decision), the conditional keys listed in the audit (`products_empty_no_match`,
`users_empty_no_match`, `products_denied`, `params_denied`, `ledger_detail_heading`), per-screen key
additions the audit says are a downgrade, and any screen that has no filter control today.

## Acceptance

1. `EmptyState kind="no-match"` renders the action snippet the caller passes; `kind="no-data"` does
   not render that action even if a caller passes it - a test asserts the negative.
2. `LoadingState` is the only one of the three that carries `role="status"`; `EmptyState` and
   `ErrorState` carry no live-region role.
3. `ErrorState` renders exactly the retry label it is given, and every migrated call site passes
   `app_retry`; a test asserts no retry label is the literal "Muat ulang" (reload is a different
   action with a different sentence).
4. `/app/loans` renders `loans_empty` with an empty list and `loans_empty_no_match` with an active
   filter that matches nothing - two different DOM texts for the two states.
5. `rg '"common_nav_vault": "Vault kas"' packages/i18n` returns 0, and no id value matches
   `vault|teller` case-insensitively while every key name still does. en values are unchanged.
6. `./task check-fast` stays green: the catalogue has no orphan and no missing key after the rename,
   which is the property that keeps the five state keys honest.

Case 4 is the one that fails on the parent commit because the two states render the same sentence
today.
