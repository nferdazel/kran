## Scope

Decision rule, in this order:

1. Measure first: run `nim check --warningAsError:all` (or the per-file equivalent already in
   `cmd_lint`) over the whole file list and count the files that go red.
2. **Zero files red** → make it fatal, no baseline, done. This is the preferred outcome.
3. **Any file red** → shrink-only baseline: `cmd_lint` keeps a per-file warning count in
   `tools/lint/warnings-baseline.txt`, sorted, one `path count` line. A file above its baseline
   fails with the warning text printed; a file below its baseline fails with "baseline stale,
   shrink it". New file with any warning fails. No append-on-failure path.

Unchanged: parallel execution, `NIMFLAGS`/`TESTFLAGS` split for `*/tests/*`, exit-code handling for
real errors, and the "failed: N files" summary line.

Out of scope: turning `hints` on or off, changing `NIMFLAGS` in a way that changes compiled output,
fixing the existing warnings themselves (that is the shrink work, done by whoever touches the file).

## Acceptance

Parent `dd48167`: `./task check` exits 0 with warnings present (invisible), which is the bug.

1. Inject `{.push warning[UnusedImport]: on.}` plus an unused import into one `apps/api/src` file →
   parent: `./task check` exit 0; here: exit 1 naming the file and the warning.
2. If the baseline path is taken: fix one listed warning without touching the baseline → exit 1
   "baseline stale"; then delete that line → exit 0. Shrink-only proof.
3. `./task check` and `./task check-fast` on the clean tree exit 0, with the warning count printed
   (either "0 warnings" or "N warnings, baseline N").
4. `./task lint` alone still works and reports the same verdict.
