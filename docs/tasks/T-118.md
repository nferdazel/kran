# T-118 — Tata kelola & SoD operator pilot (O-097/O-098/O-102)

Status: **DONE** (24 Okt 2026). **HUMAN-REVIEW-REQUIRED** (authz, mutasi kas vault, jurnal GL).

## Scope

Memo `docs/proposals/t-118-operator-governance.md` (kontribusi SME akuntansi) berisi delapan
keputusan K-1…K-8. Pemilik menyetujui **seluruh rekomendasi** (K-1(b), K-2(a), K-6 opsi A,
K-7(a), K-8). Task ini mengimplementasikan bagian strukturalnya dan meninggalkan keputusan
angka/kebijakan tetap milik pemilik.

1. **Peran admin sempit + SoD** (`platform/0032`, D-131): `ops_admin`, `ledger_admin`,
   `cash_admin`, `product_maker` dengan grant izin eksplisit; lima pasangan konflik tersemai
   (product maker/checker dan cash/ledger wajib; ledger/ops, ledger/teller, cash/teller
   nice-to-have). `platform_admin` tetap ada sebagai **break-glass**, tidak dipasangkan konflik.
   Penjaga penguncian-keluar berpindah dari "peran `platform_admin` terakhir" ke pemegang izin
   `platform.user.manage`.
2. **COA kas** (`ledger/0033`, D-132): `101` menjadi induk non-postable; `101.1 KAS DI VAULT`,
   `101.2 KAS DI TELLER`, `101.9 SELISIH KAS`; rule lama yang menunjuk `101` dipindahkan ke `101.2`.
3. **Jurnal kas teller** (`ledger/0034` + handler sesi): posting rule buka/tutup/selisih, jurnal
   **sinkron** di transaksi yang sama dengan mutasi vault, nominal nol dilewati. Kaki selisih
   memakai akun laci (`101.2`), deviasi sadar dari memo (lihat D-132 butir 3).
4. **Top-up vault maker-checker** (`teller/0035`): `POST /teller/vault/topups` hanya membuat
   pengajuan `PENDING`; `.../{requestId}/approve` oleh akun lain menulis saldo vault + jurnal
   `D <akun vault> / K <akun sumber>` + audit + event dalam satu transaksi; `.../reject` menutup
   pengajuan dengan alasan. Self-approval ditolak CHECK DB + handler.
5. **Akun vault dari parameter** (`teller.vault.cash_account`, CRITICAL,
   `NEEDS-COMPLIANCE-REVIEW`, nilai pilot `101.1`) — bukan literal kode akun di handler. Akun
   sumber wajib ASSET aktif postable dan bukan akun vault itu sendiri.
6. **Izin baru tiga segmen** (spec §13, `validPermissionCode`): `teller.vault.submit`,
   `teller.vault.approve`. Izin lama `teller.vault.topup` tetap di katalog untuk data historis,
   tidak dipakai rute mana pun. Operation id/audit action mempertahankan nama
   `teller.vault.topup.*`.

Kelima keputusan yang dulu ditunda **sudah diambil** (D-134, 24 Okt 2026; pemilik mendelegasikan):
K-3 headcount & break-glass (prosedur + runbook), K-4 format bukti, K-5 plafon kas (D-133/T-122),
K-6 pemetaan GL, K-8 `teller` tanpa vault submit/approve. O-105 juga ditutup: saldo awal vault
dijurnal lewat `ctl post-opening-balance` (`ledger/0036`). Yang **tetap** belum: UI vault
(T-121/O-103) dan angka lanjutan opsional (akumulasi harian, plafon saldo vault, toleransi variance).

  setelah dipastikan tidak ada data yang merujuk.
