# T-027 — Bootstrap admin produksi + endpoint ganti kata sandi (O-031)

Status: READY

## Kenapa
Keputusan pemilik 15 Okt 2026 (D-034): admin pertama dibuat oleh **satu perintah sekali-jalan** yang
mencetak kata sandi acak sekali, dan wajib menggantinya saat login pertama. Perintah itu belum bisa
ada karena kontrak auth hanya punya `login`/`session`/`logout`; kolom `mustChangePassword` sudah ada
di `SessionInfo` tetapi belum ada jalur yang memakainya.

## Rencana
- Kontrak + handler `POST /api/v1/auth/password` (ganti kata sandi sendiri): wajib kata sandi lama,
  patuhi kebijakan panjang/kompleksitas dari parameter DB (bukan literal di kode), cabut sesi lain
  setelah berhasil, audit `user.password_change`, dan klien TS ikut di-generate ulang.
- Jalur `mustChangePassword`: sesi yang belum mengganti kata sandi **ditolak** di operasi selain
  `session`/`password`/`logout` (kode keluar 403 dengan alasan yang jelas, i18n id + en).
- Peran CLI `ctl bootstrap-admin --username=<nama>`: hanya jalan bila belum ada user admin, mencetak
  kata sandi acak **sekali** ke stdout, menyetel `must_change_password = true`, menulis audit
  `user.bootstrap`; menolak bila admin sudah ada (tanpa opsi paksa).
- UI: form ganti kata sandi (2 tema, keyboard, axe) + pengalihan paksa saat `mustChangePassword`.
- Test: unit kebijakan panjang, integrasi (bootstrap → login → wajib ganti → sesi lain tercabut),
  e2e jalur paksa-ganti di 2 tema.

## Kriteria selesai
- [ ] `ctl bootstrap-admin` idempoten-terbatas: jalan sekali, menolak jalan kedua.
- [ ] Sesi wajib-ganti tidak bisa memakai operasi lain (diuji).
- [ ] Kata sandi lama wajib benar; sesi lain tercabut; audit tercatat.
- [ ] Kontrak + klien TS sinkron; i18n id+en lengkap; axe 2 tema lulus.
- [ ] `./task ci` hijau. Tandai `HUMAN-REVIEW-REQUIRED` (jalur auth).
