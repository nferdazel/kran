## Scope

Add `fmt-check) mkdir -p "$BUILD"; cmd_fmt_check ;;` next to `fmt)`, and one line in the usage
block. Nim only: it must not invoke prettier, eslint, or anything under `apps/web` — the JS
formatting question is not this task.

Assumption recorded here: "dispatch arm" means the subcommand arm of `./task`, not a new CI job.
The Nim job already runs `./task check`, which includes the format check, so no workflow change is
needed; if the implementation finds a CI job that should call the arm instead, it reports before
changing the workflow.

Out of scope: changing `fmt_files`, the nimpretty flags, or the `--stdin` diff technique; formatting
existing files.

## Acceptance

1. `./task fmt-check` on the clean tree → exit 0, prints the file count, no other gate runs (the
   output must not contain `archcheck`, `lint-nomagic`, `paramgen` or `i18n` lines).
2. Seed one badly formatted Nim file (e.g. 4-space indent in a `apps/api/src` file) →
   `./task fmt-check` exit 1, names the file, and prints `run: ./task fmt`.
3. `./task fmt` then `./task fmt-check` → exit 0.
4. `./task help` lists `fmt-check` with a one-line description consistent with the others.
5. `./task check-fast` still exits 0 and still contains the `format (nimpretty)` line — the arm is
   additive.
