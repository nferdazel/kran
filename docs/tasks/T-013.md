## Asumsi & keputusan (jangan disamarkan)

1. **Path repo vs server**: repo memakai `ops/scripts/*.sh` (spec §21.6); saat dipasang,
   berkas disalin ke `/srv/qouver/apps/kran/scripts/*.sh` (spec §21.5). `deploy-vps.sh`
   self-update menyalin `monorepo/ops/scripts/*.sh` → `$APP_DIR/scripts/`.
2. **`audit-consistency.sh` existing** (`~/Projects/vps/audit-consistency.sh`) membandingkan
   `deploy/deploy-vps.sh` dan belum memuat `cbs`. Karena itu disediakan
   `ops/scripts/audit-consistency.sh` yang khusus membandingkan `ops/scripts/*.sh` ↔
   `<server>/srv/qouver/apps/kran/scripts/*`. Alamat server **tidak** di-hardcode
   (`CBS_VPS` wajib diisi) supaya IP tidak tertanam di repo.
3. **Systemd hardening**: hanya `NoNewPrivileges=true` + `PrivateTmp=true` yang diaktifkan
   (aman untuk user unit). `ProtectSystem`/`ProtectHome`/`ReadWritePaths` **dikomentari**
   karena untuk user unit bisa diabaikan — menunggu verifikasi `systemd-analyze security`
   di server (tidak diklaim bekerja).
4. **FREEZE GATE**: memanggil `<bin> --role=ctl daycloser-status` (spec §21.4 #4). Bila
   binary belum ada (deploy pertama) → dilewati dengan WARN. Bila keluaran memuat
   `RUNNING`/`CLOSING` → deploy dibatalkan.
5. **Migration gate**: `--role=migrate --check|--up` dijalankan pada binary **baru**
   (`bin/cbs-api.new`) sebelum ditukar, sehingga gagal = binary lama tetap utuh
   (tafsir §21.4 #7/#8: "dibatalkan sebelum binary diganti").
6. **Filter backup non-prod** memakai ekspresi O-002: `not like '%\_verify%'`,
   `'%\_test%'`, `'%\_dev%'`.
