# T-069 — retensi tag image `localhost/kran-api:<sha>`

Status: **DONE** (19 Okt 2026). Terkait: D-066, T-067.

## Masalah

Setiap build mendeploy satu tag SHA baru dan tidak ada yang memangkasnya. Pada 19 Okt 2026 sudah ada
24 tag SHA + `:local` + `:prev` (≈2,4 GB apparent; layer dibagi, `/srv` masih 54 G bebas). Bukan
insiden, tapi bertambah tiap deploy tanpa batas.

## Keputusan

- Pemangkasan di `deploy-vps.sh` (`prune_images`), **setelah** health gate sukses — target rollback
  (`:prev`) tidak boleh hilang lebih dulu.
- Yang dipangkas hanya tag SHA 12-hex; `:local` dan `:prev` tidak pernah disentuh.
- Default simpan **5** tag SHA terbaru (`KRAN_IMAGE_KEEP`, minimal 1).
- `podman rmi` gagal (mis. image masih dipakai container berhenti) = `WARN`, bukan deploy gagal; tag
  itu akan dicoba lagi pada deploy berikutnya.

## Bukti

Harness lokal (fungsi diekstrak dari skrip, `podman`/`log` di-stub):

| Skenario | Hasil |
|---|---|
| 8 tag SHA, keep=3 | 5 tag terlama dihapus, `:local`/`:prev`/tag non-SHA tidak disentuh |
| default | 5 terbaru disimpan, sisanya dihapus |
| `rmi` gagal pada satu tag | WARN untuk tag itu, tag lain tetap dihapus, fungsi selesai normal |
| keep=0 | dipaksa minimal 1 (tag SHA terbaru selalu ada) |
| keep bukan angka | jatuh ke default 5 |

`bash -n` + `shellcheck -S warning` bersih (gate `./task check`).

## Sisa jujur

Tag yang gagal dihapus karena masih direferensikan container berhenti tetap ada sampai container itu
dibersihkan; terlihat sebagai baris `WARN` di `deploy.log`.
