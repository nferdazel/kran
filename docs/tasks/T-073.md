# T-073 — `ledger` jurnal immutable + jurnal pembalik

Status: **IN REVIEW** — r1 CHANGES-REQUIRED (BLOCKER pembalik ganda, MAJOR header tanpa baris/bypass periode); perbaikan `bac5970`, review r2 belum dijalankan (20 Okt 2026). Bukti lama (sebelum perbaikan r1): `./task ci` 742 `[OK]`; angka gate terbaru ada di laporan M1. Spec §9.1(3), §9.3, §23.

## Scope

1. Migrasi `0003_ledger_journal.sql`:
   - `ledger.journal` (header): `business_date`, `value_date`, `source_event`, `source_ref`,
     `idempotency_key` **unik**, `reversal_of` (self-FK), `created_by`, `recorded_at`.
   - `ledger.journal_line`: `line_no`, `gl_account` (FK ke `coa_account.code`), `branch_id`,
     `debit`/`credit` `numeric(24,4)` dengan CHECK tepat satu sisi > 0.
   - **Immutable di DB**: trigger menolak `UPDATE`/`DELETE` (kedua tabel) dan `TRUNCATE`.
   - **Seimbang di DB**: constraint trigger `AFTER INSERT` `DEFERRABLE INITIALLY DEFERRED` per baris;
     `SUM(debit) = SUM(credit)` dan minimal 2 baris per jurnal.
   - **Periode harus OPEN**: trigger `BEFORE INSERT` pada `journal` menolak tanggal di luar periode
     OPEN (fail-closed: belum ada periode = tidak bisa posting).
   - **Akun harus postable & ACTIVE**: trigger `BEFORE INSERT` pada `journal_line` (menutup batas
     T-072 yang hanya konvensi).
2. Domain `journal.nim`: `Journal`, `JournalLine`, validasi bentuk (>=2 baris, `line_no` unik,
   tepat satu sisi, total debit = total kredit, idempotency key/source event wajib), dan
   `reversalLinesOf` (tukar debit/kredit, nomor ulang).
3. Repo `journal_repo.nim`: `insertJournal`, `insertJournalLine`, `journalById`,
   `journalByIdempotencyKey`, `journals(filter)`, `periodOpenFor`.
4. API (composition root): baca + **pembalik**, tanpa endpoint edit/hapus:
   - `GET  /api/v1/ledger/journals?businessDate=&sourceEvent=` — daftar header (tanpa baris).
   - `GET  /api/v1/ledger/journals/{journalId}` — detail + baris.
   - `POST /api/v1/ledger/journals/{journalId}/reversal` — header `Idempotency-Key` **wajib**,
     body `{reason}` wajib. Membuat jurnal baru `reversal_of = asal` dengan baris tertukar pada
     tanggal bisnis asal; permintaan ulang dengan key sama mengembalikan jurnal yang sudah ada
     (200, idempoten), key sama untuk jurnal asal lain → 409. Audit `ledger.journal.reverse` +
     event `journal.posted` satu transaksi.
5. Izin baru (migrasi platform `0016`): `ledger.journal.read`, `ledger.journal.reverse`
   (ke `platform_admin`), institusi (dua gerbang seperti T-072).
6. Test: unit bentuk jurnal + property test **1.000 jurnal acak seimbang** dan penolakan jurnal
   tak seimbang; integrasi DB (immutability UPDATE/DELETE/TRUNCATE, deferred balance, akun
   non-postable/non-ACTIVE ditolak, periode tertutup ditolak, idempotency unik, reversal menukar
   sisi); API (401/403/400/404/409/200 + kontrak + audit/event + idempoten).

## Asumsi & keputusan (dicatat)

- **Tanpa partisi `RANGE (business_date)`** pada Fase 1 (spec §9.3 menyebut DDL itu *acuan, bukan
  final*). Alasan: (a) volume pilot kecil; (b) FK `journal_line → journal` dan constraint trigger
  deferred lebih sederhana tanpa partisi; (c) konversi ke partisi adalah pekerjaan tersendiri.
  Dicatat **D-072**; wajib ditinjau sebelum go-live volume besar.
- Jurnal **tidak** dibuat lewat HTTP manual: pembuatan berasal dari posting rule/event (T-074).
  API hanya baca + pembalik, sesuai "bukan edit".
- Koreksi = jurnal pembalik pada tanggal bisnis **asal**; bila periode asal sudah tertutup,
  pembalik ditolak (`409`) — koreksi lintas periode menunggu kebijakan akuntansi (O-077).
- `idempotency_key` untuk endpoint pembalik = nilai header `Idempotency-Key` (O-072 versi jurnal).
- Tidak ada nilai bisnis di kode: jumlah baris minimum (2) adalah invarian double-entry, bukan
  setelan institusi.
