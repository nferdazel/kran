## 2. Endpoint

- `GET /api/v1/teller/cash-transactions/{transactionId}`
  - field `CashTransaction` + `accountNo` + `narration`; izin `deposit.account.read` + gerbang
    cabang rekening; 404 bila tidak ada.
  - alasan: cetak ulang setelah printer macet, tanpa mengulang transaksi.
- `GET /api/v1/deposit/accounts/{accountId}/statement?from=YYYY-MM-DD&to=YYYY-MM-DD`
  - header rekening (`accountNo`, status, `branchId`) + baris gabungan transaksi tunai dan PB
    (masuk/keluar) dengan `transactionId`/`transferId`, `journalId`, `businessDate`, arah, nominal,
    narasi.
  - subledger, **bukan** rekonsiliasi GL; **tanpa** saldo berjalan per baris.
  - batas rentang/jumlah baris = batas teknis (bukan nilai bisnis); validasi `from <= to`.
  - izin `deposit.account.read` + gerbang cabang.

## 3. UI

- Rute di bawah `/app` agar ikut guard sesi, tetap menampilkan dokumen di layar + toolbar Cetak
  yang hilang saat print.
- CSS: `@page { size: A4; margin: 12mm }`, `thead` berulang, `break-inside: avoid` untuk total,
  `tabular-nums`, token print sudah memaksa tema terang.
- i18n id+en prefix `slip_`/`statement_`/`print_`; tanpa string hardcode.
- Format: `formatMoney(..., { decimals: 2 })`, `formatDate`, cetak `businessDate` (tanpa jam
  browser sebagai "dicetak pada").
- PII minimal: nomor rekening, nominal, narasi; tanpa nama/NIK/alamat.

## 4. Test

- Integrasi API: 401/403 cabang lain/404, rentang salah → 400, baris hanya milik rekening itu.
- E2E: stub `window.print` + `emulateMedia({ media: "print" })`, assert nav/form hilang dan field

## 6. Hasil (T-094a/T-094b)

Endpoint + rute + i18n + dokumen cetak dikerjakan di branch `feat/fase2`:

- `GET /api/v1/teller/cash-transactions/{transactionId}` → `CashTransactionSlip`
  (`transactionId`, `journalId`, `direction`, `amount`, `businessDate`, `accountNo`, `narration`).
  Izin `deposit.account.read` + gerbang cabang rekening. 404 bila id tidak ada **atau** id bukan
  transaksi tunai (mis. id PB). **Tanpa** `balanceAfter`: saldo per transaksi tidak disimpan dan
  menghitung saldo berjalan = mengarang data.
- `GET /api/v1/deposit/accounts/{accountId}/statement?from&to` → `AccountStatement` (header
  `accountNo`/`status`/`branchId` + `rows`). Baris gabungan tunai (masuk/keluar) dan PB
  (sumber/tujuan) dengan `transactionId`/`transferId` (`null` pada sisi yang tidak berlaku),
  `journalId`, `businessDate`, `direction` (`IN`/`OUT`), `amount`, `narration`; urut tanggal.
  Validasi `from <= to` + format `YYYY-MM-DD` → 400; batas **teknis** 500 baris per respons → 400
  (bukan potong diam-diam). Subledger, **tanpa** saldo berjalan.
- Rute web `/app/print/slip/[transactionId]` dan `/app/print/statement/[accountId]` (di bawah
  `/app` agar ikut guard sesi): dokumen A4 di layar + tombol Cetak yang hilang saat print.
  CSS `@page { size: A4; margin: 12mm }`, `thead` berulang, `break-inside: avoid`, `tabular-nums`;
  nav/header/footer/toolbar/form/alert disembunyikan saat print. Format `formatMoney(..., {decimals:2})`,
  `formatDate`, dan `businessDate` dicetak apa adanya (tanpa jam browser sebagai "dicetak pada").
- i18n id+en prefix `print_`/`slip_`/`statement_`; tanpa string hardcode maupun em dash.

**Batas yang tetap TIDAK diklaim** (jangan dibaca sebagai tercapai): dot-matrix/passbook, PDF
resmi/arsip/ber-tag, tanda tangan elektronik, audit cetak (tidak ada jejak siapa mencetak),
kop/logo lembaga (belum ada master cabang/`institution.*`), saldo berjalan per baris, rekonsiliasi
GL, dan layout identik antar printer. Mesin PDF server (094c) tetap ditunda (ADR-013b).
