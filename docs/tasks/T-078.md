## Scope

1. Migrasi `modules/party/migrations/0041_party_detail.sql` (expand-only, hanya CREATE):
   - `party.party_person` — detail orang: nama resmi, tanggal lahir, jenis kelamin, pekerjaan.
   - `party.party_org` — detail lembaga: nama resmi.
   - `party.address` — alamat: baris alamat, kota, kode pos (unik per party, 1:1 untuk sekarang).
   - **Setiap kolom sensitif** disimpan sebagai **tiga turunan** (pola D-069), nilai aslinya tidak
     pernah masuk DB:
     - `<col>_enc`  = ciphertext field crypto (AAD = nama tabel);
     - `<col>_bidx` = blind index HMAC-SHA256 ber-domain (hex 64) untuk pencarian kesamaan;
     - `<col>_mask` = bentuk tersamar (dua karakter terakhir), bukan rahasia.
   - CHECK DB mengikat bentuk: `_enc LIKE 'kran:enc:v1:%'`, `_bidx ~ '^[0-9a-f]{64}$'`,
     `char_length(_mask) <= 2` — penyimpanan bentuk salah gagal di DB, bukan hanya di kode.
2. Domain (`modules/party/domain/detail.nim`, murni tanpa kriptografi seperti `identity.nim`):
   tipe `PersonDetail`/`OrgDetail`/`Address`, validasi teks (panjang + karakter kontrol),
   `parseSex` (daftar dari parameter), dan `checkDetailKind` (**validasi per jenis party**:
   PERSON wajib blok `person` & dilarang `org`, dan sebaliknya).
3. Parameter baru (seed pack `base`, bukan kode): `party.person.sex_values`
   (daftar jenis kelamin yang dikenal; `NEEDS-COMPLIANCE-REVIEW` mengikuti pola daftar lain).
4. Repositori (`modules/party/infrastructure/detail_repo.nim`): upsert + baca detail/alamat.
   Modul tetap tidak menyentuh kriptografi maupun internal `platform` (archcheck rule C).
5. API (`apps/api`, composition root) — `apps/api/src/handlers_detail.nim`:
   - `PUT /api/v1/parties/{partyId}/detail` — upsert detail sesuai jenis party + alamat opsional.
     Izin `party.kyc.manage` di cabang party; audit `party.detail.upsert` (tanpa PII).
   - `GET /api/v1/parties/{partyId}/detail` — detail dalam **bentuk tersamar** (tanpa dekripsi),
     izin `party.party.read` di cabang party.
   - `POST /api/v1/parties/{partyId}/detail/unmask` — buka detail asli; izin
     `party.identity_doc.read` (izin baca PII modul) **di cabang party** + `reason` wajib; audit
     `party.detail.unmask` tanpa PII. Inilah "audit pembacaan" (spec §18.2).
   - Tanpa KEK (`KRAN_KEK_FILE` kosong): endpoint yang butuh enkripsi/dekripsi → **501**
     (fail-closed, pola MFA T-046); `GET` tersamar tetap 200 karena tidak mendekripsi.
6. Kontrak OpenAPI + rute + test. `MODULE.md` diperbarui.

## Keputusan & asumsi (dicatat, bukan ditebak)

- **Izin baca PII = `party.identity_doc.read`** (dipakai ulang, pilihan yang diperbolehkan baris
  backlog) — tidak ada izin baru, jadi tidak ada migrasi `platform`. Konsekuensi: membuka detail
  PII memakai izin yang sama dengan membuka nomor dokumen; pemisahan izin dicatat sebagai usulan.
- **Pola ciphertext per-kolom, bukan per-field-object.** Mengikuti D-069 apa adanya: tiga kolom
  untuk **setiap** field sensitif. Blind index pada field berkardinalitas rendah (jenis kelamin)
  secara harfiah lemah, tetapi uniformitas pola lebih mudah direview; batas ini disebut di sini.
- **AAD = nama tabel** (bukan `tabel.kolom`), sama seperti D-069. Konsekuensi yang **sudah**
  berlaku di D-069: ciphertext antar kolom dalam tabel yang sama tidak saling mengikat (bisa
  dipindah kolom dan tetap terdekripsi). Dicatat sebagai limit; memperketatnya = perubahan format
  crypto (review manusia).
- **Alamat opsional** pada `PUT`: bila `address` tidak dikirim, alamat yang ada dibiarkan.
  Dokumen/`person`/`org` wajib sesuai jenis party.
- **Tanggal lahir divalidasi bentuknya di handler** (`isIsoDate`, pola T-071 untuk `issuedAt`)
  dan tidak boleh melewati business date; validasi teks murni di domain.
- **Tidak ada event** untuk detail: PII tidak boleh meninggalkan modul (alasan yang sama dengan
  T-070/T-071). Detail PII dibaca ulang dari DB saat auditor membutuhkan.
- **Migration seq 0041** (>= 0041) karena 0038–0040 dipakai task lain secara paralel di worktree
  utama; urutan migrasi global `(seq, module, filename)`.
