1. `cmd_lint_web` fails closed: missing `node_modules` is `die`, not `skip`. The one intentional
   escape is `KRAN_ALLOW_NO_JS=1`, which prints an explicit skip line that names the variable, the
   same shape as `KRAN_ALLOW_NO_DB` for tests. Same for the `packages/ui` svelte-check branch,
   which currently skips too.
2. `ci-fast` gains the `packages/ui` vitest run (`contrast`, `components`, `money`, `shell`) — the
   tests already exist in `packages/ui/tests/`, only the wiring is missing. Keep them out of
   `check` (no JS needed there) and keep `e2e` as is.
3. One CI job runs `./task ci-fast`, so the gate that P0a names actually executes in CI. `ci-fast`
   calls `require_db`, so use the job that already has a Postgres service rather than adding a
   second database: extend that job with the step, or add a job with the same service block if the
   existing one cannot carry it. Say which you picked and why in the commit message. No new
   dependency, no version pinning beyond what the workflow already uses.

Out of scope: `lint-nomagic` (T-174), `fmt-check` dispatch (T-178), any change to `./task e2e`
beyond what breaks if a helper moves, and any prettier or TS formatting rule.
