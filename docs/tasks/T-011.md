## Scope

1. `tools/scaffold/` (Nim; pola `lib.nim` + `main.nim` + `tests/`) menghasilkan kerangka modul
   baru di `modules/<nama>/`.
2. Modul contoh `modules/hello/**` **di-generate oleh tool itu sendiri** (bukan tulis tangan),
   lalu dibuktikan hijau lewat `./task check` / `./task test` / `./task ci`.
3. Test `tools/scaffold/tests/tscaffold.nim` menulis ke `$TMPDIR`, memverifikasi berkas yang
   diharapkan, isi tidak kosong, penolakan nama tidak sah, dan larangan menimpa modul existing.
4. Wiring `./task scaffold` di runner (satu fungsi `cmd_scaffold` + satu `case`).
5. Laporan ini + `docs/PROGRESS-T011.md`.

## Keputusan desain (dan alasannya)

1. **Nama berkas internal memakai peran, bukan nama modul.** `domain/core.nim`,
   `application/use_case.nim`, `tests/t<sanitized>.nim`. BACKLOG T-011 meminta validasi nama
   `[a-z][a-z0-9-]*` (boleh `-`), sedangkan **Nim menolak `-` di nama modul/berkas** (diuji:
   `invalid module name`). Dengan nama peran + `-`→`_` pada nama test, modul ber-tanda-hubung
   tetap menghasilkan kode yang bisa dikompilasi. Spec §5.5 sendiri menginginkan konvensi nama
   identik antar modul — nama peran justru memperkuat itu.
2. **`seeds/params.yaml` = daftar kosong `[]` (valid).** Menambah parameter contoh akan memaksa
   regenerasi artefak `shared/kernel/generated/paramkeys.nim`, `packages/contracts/src/generated/params.ts`,
   dan `packs/*`; itu di luar scope T-011 dan menambah blast radius. Kosong tetap "minimal tapi
   valid" dan `paramgen --check` lolos tanpa regenerasi (dibuktikan).
3. **Migrasi hanya membuat schema** (`CREATE SCHEMA IF NOT EXISTS <nama>`), sesuai §6.3
   (satu modul = satu schema). Belum ada tabel; migrasi tetap non-kosong (ditolak `dbtools` bila
   kosong) dan expand-only. Nama schema dikutip hanya bila memuat `-`.
4. **Tidak menimpa & `--dry-run`.** Scaffold menolak bila `modules/<nama>` sudah ada (scaffold
   bukan pengubah berkas milik manusia); `--dry-run` hanya mencetak rencana. Idempotensi
   "diam-diam" sengaja tidak diambil karena berkas hasil scaffold diedit manusia.
5. **i18n namespace BELUM di-generate** (spec §5.5 menyebutnya). `packages/i18n` (T-010) belum
   ada; membuat `packages/i18n/messages/` akan memicu `./task i18n` membangun `tools/i18ncheck`
   yang belum ada → gate merah. Ditunda sampai T-010 agar tidak melemahkan gate. `MODULE.md`
   tetap mendokumentasikan prefix namespace yang harus dipakai.
6. **Import di kode hasil selalu relatif & aman** (`./domain/core`, `../domain/core`) supaya
   tidak bergantung pada `-p:modules` dan tidak menyentuh nama modul ber-tanda-hubung.

## Batas / yang tidak bisa diverifikasi (jujur)

- **Test integrasi tidak dijalankan** (`CBS_DATABASE_URL` kosong di worktree ini) — termasuk
  `itplatform`/`itcalendar`/`itpool`. Bukan kegagalan; memang SKIP by design.
- **e2e/Playwright tidak dijalankan** (`apps/web` belum ada, T-010).
- **Modul ber-tanda-hubung belum diuji-kompilasi di test otomatis.** Test hanya memverifikasi
  nama test tersanitasi; kompilasi `my-mod` sempat dicoba manual (probe) dan berhasil dengan
  template ini, tetapi tidak dijadikan test karena butuh memanggil `nim` dari test.
- **i18n namespace modul belum ada** (menunggu T-010) — lihat keputusan 5.
- **Bukan jaminan bisnis**: isi `hello` hanya contoh; domainnya sengaja tidak bermakna bisnis.
